# RE:volution Mod v1.5.0

## Назначение релиза

`v1.5.0` переносит текущий пакет ZBT-баланса в canonical Balance Core snapshot и исправляет progression/runtime-контракты, необходимые для его корректной работы.

Численные значения баланса этого релиза являются **Draft для ЗБТ**, если отдельно не указано иное. Стабильность релиза означает стабильность реализации и воспроизводимость snapshot, а не статус Final для всех чисел.

## Nested Rune Purchase Progression

Purchase progression теперь выводится только из фактических per-rune ranks.

Цикл работает вложенно:

- сначала собираются 26 `Обычных`;
- первый rank-up оставляет `1 Улучшенную + 0 Обычных`;
- затем `Обычные` собираются заново вокруг уже повышенных рун;
- после заполнения `Улучшенных` аналогично строится `Продвинутая` коллекция.

Для текущего purchase rank отдельно считаются:

- `lowerProgress` - число рун ровно текущего собираемого ранга;
- `higherRuneCount` - число рун уже выше текущего собираемого ранга;
- `coveredCount = lowerProgress + higherRuneCount`.

Исторические `purchaseIndex`, `currentCollectionRank` и `nextPurchaseCost` не используются.

## Purchase и duplicates

Базовая purchase curve для `lowerProgress=0..25`:

`20, 20, 22, 26, 32, 43, 62, 95, 119, 149, 186, 232, 291, 363, 454, 568, 710, 888, 1110, 1390, 1730, 2170, 2710, 3390, 4240, 5290`.

Фактическая цена:

`PurchaseCost = BaseCurve(lowerProgress) × 1.15 ^ HigherRuneCount`.

Результат округляется до ближайшего целого через `HALF_UP`, потому что runtime-ресурсы целочисленные.

Duplicate:

- coin refund отсутствует;
- progression не двигается;
- награда - `rune_dust`;
- `DuplicateReward = max(1, round(PurchaseCost × 0.0003))`;
- расчёт использует актуальную фактическую цену попытки.

## Enhancement

ZBT enhancement curve определена для общего collection-global уровня `1..50`.

Контрольные cumulative значения:

- `+10 = 73 Dust`;
- `+20 = 531 Dust`;
- `+30 = 2936 Dust`;
- `+40 = 15550 Dust`;
- `+50 = 81520 Dust`.

`+50` является текущей границей ZBT-таблицы. Запросы, пересекающие границу, server-side отклоняются; GUI помечает недоступный bulk как превышающий лимит. Усиление остаётся свойством слота и переживает rank-up/revert.

## Rank-up и revert

Rank-up оплачивается `rune_shards`. Стоимость следующего повышения определяется количеством рун, уже находящихся выше source rank. Таблица 26 последовательных цен:

`1, 1, 1, 2, 2, 3, 3, 4, 5, 6, 8, 10, 12, 15, 18, 22, 27, 33, 40, 49, 60, 73, 89, 108, 131, 159`.

Сумма всех 26 повышений одного перехода - `882` осколка.

Rune Rank Revert сохраняет контракт v1.4.9 и теперь читает server-side policy из Balance Core:

- `revert_allowed_from_rank = 3`;
- `revert_steps = 1`.

Для текущей модели это `Продвинутая -> Улучшенная`. `Улучшенная -> Обычная` запрещено. Refund отсутствует, enhancement сохраняется, повторный rank-up оплачивается полностью. Жест GUI остаётся `CTRL + ПКМ = Ослабить`.

Revert полного Advanced-сета одной руны даёт factual state `1 Improved + 25 Advanced`, `coveredCount=26`, поэтому revert не открывает бесплатный purchase slot.

## Rune Balance и stacking

Collection 1 использует 26 slots и 11 семейств из текущего ZBT snapshot.

Основные stacking-правила:

- flat складывается;
- одинаковые multiplier-каналы перемножаются;
- vulnerability складывается как процентный бонус;
- targeted power складывается и добавляется непосредственно к flat целевой группы до общих multipliers;
- proc chance берёт максимум;
- proc multiplier берёт максимум;
- rage multiplier берёт максимум;
- enhancement multiplier = `1 + 0.10 × enhancementLevel`.

Rage активируется от hit и повторными ударами обновляет duration. Для рангов используются `4 / 5 / 6` секунд.

## Poison / AoE

`poisonDamage` трактуется как DPS-бюджет, а не как damage одного тика.

- 5 poison ticks/sec;
- один tick каждые 4 MC ticks;
- общий AoE multiplier для 1..10 целей: `1.00, 1.50, 1.80, 2.00, 2.20, 2.30, 2.40, 2.50, 2.60, 2.70`;
- для количества целей выше 10 используется cap `2.70`;
- per-target tick = `BasePoisonDPS × AoEMultiplier(N) / N / 5`.

## Location 1

Bundled Balance Core snapshot теперь содержит явные ZBT overrides HP и reward для всех `Mob1_1 .. Mob1_41`.

Stage 41 остаётся фиксированным boss:

- HP: `30,000,000`;
- reward: `15,000,000 coins`.

Repeat-kill boss scaling не добавляется.

## Проверки

Добавлены/обновлены regression tests для:

- factual nested purchase progression;
- purchase pressure и duplicate formula;
- rank-up index по фактическому higher-rank count;
- enhancement curve и cap `+50`;
- data-driven revert policy и revert-loop invariant;
- Rune Effects и direct targeted-power stacking;
- Location 1 bundled overrides;
- Poison/AoE DPS distribution;
- ZBT combat smoke для manual CPS `5 / 10 / 15 / 20`.

Smoke является диагностикой Draft-баланса, а не Final pacing gate. На текущем snapshot он показывает очень большой разрыв между full Ordinary и full Advanced профилями; значения сохранены буквально и не были автоматически перебалансированы.

## Что не меняется

- Rank 4 не балансируется и не добавляется.
- Mongo schema не меняется.
- Balance Core schema version остаётся `1`.
- Google API/OAuth не добавляется в gameplay-мод.
- Mob identity, population, spawn geometry, models/textures и world topology не становятся Balance Core fields.
