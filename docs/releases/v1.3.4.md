# RE:volution Mod v1.3.4

`v1.3.4` завершает Realm foundation и зафиксирован как выпущенный и принятый runtime baseline перед следующими этапами roadmap.

## Realm model

- Realm 0 — существующий административный overworld / dimension `0`; в автоматическом распределении игроков и startup sync не участвует.
- Realm 1 — dimension `201`, основной player Realm и эталон сохранённого мира для стартовой подготовки Realm 2/3.
- Realm 2 — dimension `202`.
- Realm 3 — dimension `203`.
- При обычном входе игрок назначается в наименее населённый Realm из `1..3`.
- При равной минимальной населённости выбор выполняется случайно среди связанных минимумом Realm.
- `/realm join <realmId> [player]` остаётся административной командой и поддерживает Realm 0.
- Стартовая точка player Realm: `0,64,0`.

Realm ID, Dimension ID, будущие Location/Mob Position ID и UUID сущности считаются отдельными идентификаторами.

## Startup sync

На каждом старте dedicated-сервера `DIM202` и `DIM203` полностью подготавливаются из сохранённого `DIM201` до `loadAllWorlds` Forge.

- Во время работы сервера Realm 1/2/3 независимы.
- Изменения игроков в Realm 2/3 сбрасываются на следующем старте.
- Realm 1 сохраняется и остаётся source-of-truth.
- Realm 0 не изменяется startup sync.
- MongoDB, общие player data и посторонние dimensions не копируются этим механизмом.
- Команда `/realm sync` не добавлялась.
- Добавлены защита от незавершённой транзакции, подготовка обеих копий перед публикацией и восстановление при ошибке.
- Сохранённые блоки стартового чанка не перезаписываются при обычном входе или рестарте.

Подробный контракт: [Realm startup sync](../realm-startup-sync.md).

## Build / Test world workflow

Обычный тестовый launcher не копирует Build world в Test автоматически. Realm 0 переносится только отдельными ручными скриптами:

- Build → Test;
- Test → Build.

Скрипты сохраняют dimensions и player data назначения, не копируют MongoDB, `mods` или `config` и не запускают Forge как побочный эффект.

## Проверки и приёмка

Для `v1.3.4` были пройдены автоматические CI-проверки и ручная runtime-приёмка на реальном Forge-сервере с клиентом. В частности подтверждено:

- persistence Realm 1;
- сброс Realm 2/3 к свежей копии текущего Realm 1 после рестарта;
- отсутствие изменений Realm 0 при startup sync;
- работа `/realm join 0`;
- отображение Realm в клиентском HUD;
- корректная startup-последовательность;
- успешные `preflight -CheckOnly`, manual copy `-CheckOnly` и `preflight-and-run.ps1 -PrepareOnly`.

## За пределами v1.3.4

В этот релиз намеренно не входят:

- Location / Mob Position foundation;
- новая система fixed mobs;
- contribution / rewards / HP rollback;
- progression;
- scaling.

Эти изменения продолжаются отдельными версиями `v1.3.5`–`v1.3.9`, чтобы не смешивать контракты Realm foundation с последующими gameplay-системами.
