# v1.2.6 — фундамент платного пробуждения

Версия v1.2.6 включает платное пробуждение рун на уже подготовленной основе экономики и прогрессии. Сервер остаётся единственным источником истины для возможности пробуждения, цены, ресурса оплаты и фактического списания.

## Изменения

- Подключена конфигурация оплаты пробуждения через `awakeningResourceForStatus`, `awakeningCalculationType`, `awakeningCost` и `isAwakeningPaymentConfigured`.
- Перед списанием сервер сначала получает решение прогрессии о возможности пробуждения.
- Если пробуждение запрещено, коллекция не меняется и ресурс не списывается.
- Перед успешным пробуждением сервер проверяет доступный баланс выбранного ресурса.
- Поддерживаются режимы расчёта `FIXED`, `BY_RANK` и `FORMULA`, а также глобальный и статусный event-множители.
- Клиент получает фактический ресурс оплаты и рассчитанную цену с сервера.
- Цена пробуждения отображается в левой части блока действий, рядом с самим пробуждением.
- **Улучшение руны остаётся отдельной механикой и в v1.2.6 не реализовано.** Его UI не использует цену пробуждения и продолжает показывать отсутствие заданной цены.
- Legacy-действие `upgrade_rune:` сохранено для сетевой совместимости текущего пробуждения, но не означает существование реализованной механики улучшения.

## Экономика

Для статуса **Яд** используется технический baseline: **100 Пыли рун за пробуждение**. Это значение нужно для проверки механики и не считается финальным балансом полной экономики рун.

Покупка рун и компенсация дубликатов из предыдущих версий работают без изменения своей модели.

## Прогрессия

Правила прогрессии из v1.2.5 сохранены:

- выбранная руна повышается на следующий ранг;
- руны текущего ранга коллекции расходуются;
- уже полученные руны более высокого ранга сохраняются;
- нельзя перейти к следующему этапу, пока коллекция не соответствует требованиям;
- **Продвинутая** остаётся максимальным рангом.

## Проверка

Runtime-проверка подтвердила корректное отображение цены пробуждения, списание Пыли рун при разрешённом пробуждении и правильное разделение UI пробуждения и ещё не реализованного улучшения.

CI feature-ветки, develop и main также успешно пройден до подготовки релиза.
