# RE:volution v2.11.0

## Основное

`v2.11.0` добавляет отдельную permanent server-authoritative систему **Unique Rune Collections**, не заменяя и не смешивая её с обычной Rune System.

В релиз входят три фиксированные коллекции по 26 рун:

- `CRYSTAL_COLLECTION` - покупка за Crystals, дубликаты конвертируются в Pearl;
- `DAILY_COLLECTION` - одна factual награда в день без дубликатов текущего цикла;
- `OFFERINGS_COLLECTION` - покупка за существующие Offerings после фактического открытия God Worship, без duplicate compensation.

Каждая коллекция имеет собственный permanent state, текущую rarity и progression `X/26`. Gameplay rarity progression: `COMMON -> IMPROVED -> ADVANCED -> MYTHIC`; `ANCIENT` остаётся зарезервированной и gameplay-недоступной.

## Unlock и acquisition

Crystal и Daily collections открываются по server-side progression milestone из Balance Core. Offerings Collection открывается только если у игрока фактически доступен God Worship.

Все acquisition actions server-authoritative: клиент передаёт только intent, сервер повторно проверяет unlock, баланс, completion state, nonce и eligibility.

Crystal purchase:

- списывает Crystals;
- выбирает Rune на сервере;
- новая Rune добавляется в текущий rarity cycle;
- duplicate не двигает `X/26` и выдаёт data-driven Pearl compensation.

Daily claim:

- доступен один раз на factual epoch day;
- выбирает только Rune, которой ещё нет в текущем cycle;
- не может выдать duplicate;
- выдаёт дополнительный data-driven resource reward.

Offerings purchase:

- списывает существующие persistent Offerings;
- duplicate разрешён;
- duplicate не выдаёт компенсацию.

## Pearl и Crystal enhancement

Добавлен permanent ресурс `pearl` для Unique Rune enhancement.

Enhancement доступен только Crystal Collection. Стоимость задаётся Balance Core отдельно для Rune и уровня, имеет data-driven tail и не содержит Java hard cap по уровню.

Enhancement хранится независимо от rarity cycle и сохраняется через Awakening и rollback.

## Awakening

Awakening доступен только после factual `26/26` текущей rarity коллекции.

При успешном Awakening:

- сохраняется rollback snapshot предыдущего cycle;
- текущая коллекция очищается;
- rarity повышается на один gameplay tier;
- выбранная Rune становится первой Rune нового tier;
- permanent enhancement state не теряется.

После `MYTHIC` дальнейший gameplay Awakening отсутствует.

## Rollback

Rollback платный и требует отдельного явного подтверждения в UI.

Первый action только переводит UI в warning/confirmation state. Повторный подтверждённый action server-side повторно проверяет состояние и стоимость.

Успешный rollback:

- списывает data-driven Crystal cost;
- восстанавливает exact pre-Awakening rarity и factual owned set из сохранённого snapshot;
- не выдаёт compensation;
- очищает использованный rollback snapshot, поэтому один rollback нельзя применить повторно.

## Modifier layer

Unique Rune effects входят в существующий server-authoritative effect pipeline отдельным слоем.

Для earned resources порядок поздних модификаторов:

`normal gameplay modifiers -> Unique Rune -> Achievement -> Aura -> persisted earned amount`.

Для damage runtime Unique Rune handler регистрируется до поздних `GOD` и `AURA` handlers. Architecture guard фиксирует этот порядок и не позволяет случайно переставить layer.

Rune definitions могут содержать additive stat effects и data-driven mechanical metadata. Эффекты рассчитываются только из factual permanent ownership/rank/enhancement state.

## Persistence и миграция

Unique Rune state хранится в существующем player document через отдельный Mongo repository/adaptor.

Сохраняются:

- текущая rarity каждой коллекции;
- factual owned Rune ids и их rarity;
- Crystal enhancement levels;
- rollback snapshot;
- последний Daily claim day;
- schema/migration state, необходимый для backward-compatible чтения.

Система не меняет ordinary Rune ownership, Rune collection progression, Pet, Aura, Achievement или God Worship state.

## Network и replay protection

Добавлены dedicated discriminators:

- `25` - C2S Unique Rune action;
- `26` - S2C Unique Rune snapshot.

Существующие discriminators, включая зарезервированные `5/6` и текущие `7..24`, не меняются.

Mutating actions используют monotonic request nonce. Duplicate/lower nonce отклоняется сервером. Client nonce seeded от текущего времени, чтобы reconnect не возвращал клиента к старому низкому значению при сохранённом server replay state.

Snapshot server-authored и содержит factual collection state, balances и action availability; клиент не предсказывает ownership или эффекты.

## Share

Unique Rune Share формируется сервером только для factual owned Rune.

Payload содержит collection, rarity, Crystal enhancement и фактически рассчитанные stat effects. Нельзя поделиться Rune, которой нет в permanent state игрока.

## UI

Добавлен отдельный functional-first экран Unique Rune Collections с тремя коллекциями.

UI показывает:

- unlock/lock state;
- текущую rarity;
- `X/26` progression;
- owned Rune state;
- Crystal / Pearl / Offerings balances;
- purchase / Daily claim actions;
- Crystal enhancement;
- Awakening;
- Share;
- rollback warning и отдельное confirmation действие.

UI остаётся server-authored skeleton: final visual polish не является scope `v2.11.0`.

## Balance Core

Добавлен overlay `balance/v2.11.0-unique-runes.json`.

Он задаёт:

- три collection definitions по 26 Rune;
- unlock milestones;
- acquisition costs;
- duplicate Pearl compensation;
- Daily extra reward;
- rollback Crystal costs;
- rarity scaling;
- per-Rune enhancement curves;
- stat/mechanical effect definitions.

Текущие числовые значения имеют статус **ZBT Draft**. Stable в `v2.11.0` - архитектура, persistence, server authority, modifier ordering и data-driven contract, а не финальный production balance.

## Проверки

Regression coverage включает:

- ровно три коллекции по 26 Unique Rune;
- gameplay rarity progression и reserved `ANCIENT`;
- per-Rune Crystal enhancement curves и unlimited tail;
- Crystal acquisition, duplicate -> Pearl и replay rejection;
- Daily one-per-day и отсутствие duplicates;
- Offerings duplicate без compensation;
- `26/26` Awakening;
- explicit rollback confirmation и exact snapshot restore;
- ownership-only Share;
- запрет enhancement вне Crystal Collection;
- architecture topology для Unique Rune adapters;
- discriminators `25/26` и сохранение старых packet ids;
- modifier ordering `Unique Rune -> GOD -> AURA` для damage handlers;
- resource asset contract для нового Balance overlay;
- полный существующий regression suite проекта.
