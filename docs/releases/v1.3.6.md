# RE:volution Mod v1.3.6

`v1.3.6` подключает runtime мобов к фундаменту Location + Mob Spawn из `v1.3.5` и добавляет рабочий flow массового заполнения mob-zones.

## Runtime Mob Spawn

- Один физический spawn-slot создаёт ровно одного моба в каждом Realm, к которому относится его scope.
- Несколько spawn-slot могут ссылаться на один и тот же логический mob definition.
- `PLAYER_REALMS` разворачивает одну конфигурацию в Realm 1, Realm 2 и Realm 3 с одинаковой геометрией и разными dimension ID.
- `REALM_0` остаётся отдельным explicit scope для специальных случаев.
- Выгруженные Realm не поднимаются только ради managed mobs. Runtime ждёт фактической загрузки dimension игроком.

## Mob zones

Обычная игровая зона моба адресуется парой `locationId + mobSlotId`.

Пример: мировая Location `1` может содержать Mob Slot `1`, `2`, `3` и далее. Каждый slot имеет собственный центр и радиус. Это позволяет держать примерно 8-10 разных групп мобов внутри одной мировой локации без смешивания их геометрии.

### Создание зоны

`/custommob location set <locationId> <mobSlotId> <radius>`

Центр берётся из текущей позиции администратора по X/Z. Повторный `set` переносит/изменяет зону и очищает её старое заполнение, после чего нужно снова выполнить `populate`.

### Заполнение зоны

`/custommob location populate <locationId> <mobSlotId> <mobName> <count>`

Команда автоматически создаёт физические spawn-slot для указанного системного моба:

- 50% `FIXED_POINT + ROAMING`;
- 50% `RANDOM_AREA + ROAMING`;
- при нечётном `count` лишний моб относится к `FIXED_POINT`;
- `STATIONARY` не удалён из runtime и остаётся для будущих боссов/спец-мобов, но `populate` его не использует.

Fixed-точки распределяются детерминированно по всей площади круга golden-angle layout, а не только по окружности. После смерти fixed-моб возвращается в свою закреплённую точку.

Для `RANDOM_AREA` каждый игровой спавн и респавн заново независимо выбирает X/Z внутри круга. Новая точка может случайно совпасть с предыдущей. Y ищется по безопасной поверхности runtime.

## Проверка зоны

`/custommob location here` показывает все mob-zones, внутри которых находится игрок. При пересечении выводятся все совпавшие зоны вместе с `locationId`, `mobSlotId`, центром, радиусом, mobName, count и split fixed/random.

`/custommob location list <locationId>` показывает все mob-slot выбранной мировой Location.

## Roaming

`ROAMING` использует ту же круглую область, что и spawn-zone. При приближении к краю моб получает путь внутрь. Если он выходит дальше примерно чем на два блока за радиус, он возвращается на fallback своей текущей жизни.

Для fixed-моба fallback всегда его закреплённая точка. Для random-моба fallback действует только до следующей смерти, после которой выполняется новый random roll.

## Низкоуровневые команды

Старые `/custommob spawn set|list|remove` сохраняются как низкоуровневый инструмент для ручной настройки, Realm 0, будущих боссов и специальных сценариев.

После изменения конфигурации managed mobs автоматически перезагружаются.

## Не входит в v1.3.6

Contribution/reward rework, HP rollback, progression и scaling остаются следующими этапами и в эту версию не добавляются.
