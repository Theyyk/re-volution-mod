# RE:volution Mod v1.3.12

`v1.3.12` закладывает фундамент автоматического создания новых стадий Location: единый шаблон, детерминированный seed-driven plan и отдельный provisioning service без привязки planning-логики к Minecraft world mutation.

## Что добавлено

### Location Generation Foundation

- Добавлен immutable `LocationTemplate` как контракт геометрии и допустимых семейств вариаций.
- Добавлен pure `LocationGenerationPlanner`, не зависящий от Minecraft, MongoDB или Forge lifecycle.
- Один и тот же seed, Location/stage и anchor всегда дают одинаковый generation plan.
- План содержит rotation стадии и будущие placements для полян цветов, групп деревьев и камней.
- Добавлен `LocationProvisioningService`, который сохраняет только stage geometry через существующий `LocationRepository`.
- Population мобов остаётся отдельной административной операцией.

### Команда создания стадии

```text
/location create <locationId> <mobSlotId> [seed]
```

Команда:

- создаёт пустую `MOB_ZONE` вокруг текущей позиции администратора;
- использует radius базового template;
- при отсутствии явного seed выводит стабильный seed из world seed, Location/stage и block anchor;
- при явном seed использует переданное signed 64-bit значение;
- не создаёт мобов и не назначает Boss Zone;
- сразу обновляет runtime topology, поэтому рестарт сервера после создания не нужен;
- отклоняет duplicate stage;
- не позволяет создать stage после уже существующей Boss Zone в той же Location.

## Архитектура

Planning и применение к Minecraft миру разделены намеренно. `LocationGenerationPlan` является чистым описанием результата, а текущий provisioning сохраняет только конфигурацию зоны. Позднее отдельный world-generation adapter сможет применить REBuilder/template assets или block operations, не меняя seed contract и application service.

## Проверки

JUnit coverage проверяет:

- детерминизм одинакового seed;
- различие вариаций для разных seed;
- нахождение planned decorations внутри radius template;
- стабильность default seed;
- создание пустой `MOB_ZONE` без mob spawns;
- запрет duplicate stage;
- запрет stage после Boss Zone;
- допустимость stage перед уже существующей Boss Zone.

Существующий regression/architecture suite также должен оставаться зелёным.

## Не входит в v1.3.12 foundation

На этом этапе намеренно не реализованы:

- автоматическая установка блоков и конструкций;
- финальные строительные template assets;
- terrain sculpting;
- автоматический `populate`;
- автоматическое назначение Boss Zone;
- автоматическая установка transition points;
- сложные правила биомов и декора.

Эти части будут добавляться поверх текущего deterministic contract, когда строительные шаблоны будут готовы.
