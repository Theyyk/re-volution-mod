# RE:volution Mod v1.3.12

`v1.3.12` закрывает большой цикл Location 1: создание стадий через REBuilder, стабильная progression/transition topology, канонические `MobL_N + population`, автоматический финальный Boss Zone и полный читаемый набор внешнего вида 1–41.

## Location provisioning

Каноническая команда:

```text
/location create <locationId> <mobSlotId>
/location create <locationId> <mobSlotId> <x> <y> <z>
```

- Stage создаётся детерминированно из world seed, Location/stage и anchor coordinates.
- Физическая сборка выполняется через настроенный REBuilder template.
- Remote build поддерживает ранее не загруженные chunks, несколько Forge tickets для больших шаблонов и удерживает точный requested anchor во время prepare/build.
- Provisioning сохраняет stage geometry, trigger, generation metadata и автоматически планирует transition point там, где это возможно.
- Ошибка persistence/build компенсируется существующим rollback path; незавершённая операция не должна оставлять частично созданную stage.

## Канонические мобы и population

Для каждой stage используется стабильное техническое имя:

```text
Mob<locationId>_<mobSlotId>
```

Например, `1/41 -> Mob1_41`.

- При отсутствии definition создаётся default: `HP=1`, reward `coins x1`.
- Уже настроенные HP/reward/type не перезаписываются.
- Новая stage получает population `1` автоматически.
- Для существующих Location 1 stages 1–41 пустая/тестовая population один раз приводится к `Mob1_N`.
- После перехода на канонические имена последующие изменения количества spawn slots сохраняются и не сбрасываются при restart.
- Техническое имя `MobL_N` не выбирает модель/текстуру; appearance остаётся привязан к Location + mob slot catalog.

## Boss Zone

Финальная configured stage каждой Location является boss stage автоматически.

- Runtime progression всегда использует максимальный configured `mobSlotId` как boss.
- Persisted layout поддерживает тот же инвариант: финальная stage хранится как единственная `BOSS_ZONE`, предыдущие — как `MOB_ZONE`.
- При добавлении новой последней stage Boss Zone переносится автоматически.
- Нормализация типа зоны не пересоздаёт geometry и сохраняет name/radius/transition point/yaw/pitch.
- `/stage location setboss` и `clearboss` остаются legacy/admin-командами совместимости, но обычный `/location create` не требует ручного назначения boss.

## Progression и переходы

- Progression продолжает использовать общий server-authoritative resolver.
- Финальный boss открывает первый configured stage следующей Location.
- Trigger transition и Fast-auto разделены: `/stage auto` относится к boundary trigger automation, Fast-auto — к немедленному переходу после unlock.
- Boundary transition остаётся armed после валидного пересечения ring и не теряется из-за нормальной скорости игрока.
- Destination chunks подгружаются до safety/collision проверки.
- Post-teleport cooldown не должен поглощать валидный вход в следующую transition zone.

## Location 1: внешний вид 1–41

- Все 41 runtime slot имеют статический appearance contract.
- Обычные atlas — `64x64`, `ancient_forest_guardian` — `128x128`.
- Зафиксирован точный Minecraft 1.12.2 `ModelBox` six-face UV contract.
- `moss_turtle` восстановлен как regression baseline.
- Остальные PNG приведены к читаемому test-ready состоянию: ожидаемые материалы на ожидаемых частях, различимые head/body/limbs/extras.
- Сильная художественная дифференциация вариантов intentionally перенесена в будущий visual polish pass.

## Совместимость существующего мира

Для уже созданных Location 1 stages 1–41 v1.3.12 не должна пересоздавать:

- stage geometry;
- world/build blocks;
- transition points;
- trigger topology.

При старте выполняется только reconciliation gameplay metadata: canonical mob/population и финальный Boss Zone contract.

## Проверки

Автоматический suite покрывает, среди прочего:

- deterministic Location plans и provisioning;
- duplicate/rollback/error paths;
- unloaded-chunk и Forge ticket behavior contracts;
- canonical `MobL_N` creation и сохранение пользовательского balance;
- idempotent population migration;
- автоматический runtime/persisted final-stage boss;
- сохранение geometry/transition point при смене zone kind;
- progression/transition/Fast-auto contracts;
- packaged static resources и Location 1 texture asset contract.

Перед stable promotion финальный tested `develop` SHA должен пройти exact-head CI и полный DEV publication chain.
