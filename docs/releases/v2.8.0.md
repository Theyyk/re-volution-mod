# RE:volution v2.8.0

## Основное

- Добавлена функциональная God Worship System из пяти независимых God-треков с техническими идентификаторами `GOD_1` ... `GOD_5`.
- Каждый God имеет собственные unlock/upgrade cost, charge, buff, cooldown и damage-channel contract.
- Уровни God не имеют hard cap; уровень усиливает только величину God buff по data-driven curve.
- Текущие числовые значения God Worship имеют статус ZBT Draft и остаются настраиваемыми через Balance Core.

## Каналы и эффекты

- `GOD_1`: основной `POISON_DAMAGE_MULTIPLIER`, secondary foundation `CLICK_DAMAGE_MULTIPLIER`.
- `GOD_2`: основной `DECAY_DAMAGE_MULTIPLIER`, secondary foundation `BURNING_DAMAGE_MULTIPLIER`.
- `GOD_3`: `ALL_DAMAGE_MULTIPLIER`, без secondary channel.
- `GOD_4`: основной `WITHER_DAMAGE_MULTIPLIER`, secondary foundation `CURSE_DAMAGE_MULTIPLIER`.
- `GOD_5`: основной `BLEEDING_DAMAGE_MULTIPLIER`, secondary foundation `CLICK_DAMAGE_MULTIPLIER`.
- God modifiers применяются отдельным late layer после обычного shared `EffectResolver`; `ALL_DAMAGE` применяется один раз.
- Secondary channels включаются только feature gate `GOD_SECONDARY_BUFFS`; primary и secondary используют одну и ту же величину X.
- Добавлен future effectiveness extension point для последующего Pet/season усиления всех Gods, конкретного God или конкретного God-channel без реализации нового Pet-контента в v2.8.0.

## Lifecycle и ручное поклонение

- Состояния God: `LOCKED`, `CHARGE`, `BUFF_ACTIVE`, `COOLDOWN`.
- Unlock переводит God на level 1 и начинает `CHARGE`.
- Ручной Worship-click заполняет charge; последний обязательный manual step активирует buff.
- После фактического окончания buff начинается cooldown, затем God возвращается в `CHARGE`.
- Cooldown хранится абсолютным timestamp и проходит в реальном времени во время logout/restart/offline.
- Во время cooldown ручной Worship-click уменьшает оставшееся время на data-driven величину.
- Passive charge существует только пока открыт God Worship panel; закрытое меню и offline-время passive charge не дают.

## Offerings, Auto Worship и activation modes

- Добавлен постоянный ресурс `Offerings`, генерируемый только на фактическом интервале активного God buff.
- Offline settlement математически ограничен `buffActiveUntil`, идемпотентен и не выдаёт лишнее после relog/restart.
- Auto Worship может тратить Offerings на charge или сокращение cooldown и обрабатывает включённые Gods детерминированно без скрытого приоритета.
- Без Auto Activation автоматизация не может выполнить последний manual charge step и сама активировать buff.
- Поддерживаются режимы `MANUAL`, `AUTO_WHEN_READY`, `LINKED_TO_GOD`.
- Один God может служить trigger для нескольких linked Gods; self-link запрещён.
- Циклические linked-конфигурации bounded и не могут вызвать рекурсивную бесконечную активацию.
- Linked God, который ещё не готов, просто пропускается без ошибки.

## Permanent duration и feature gates

- Добавлен постоянный unlimited meta-upgrade длительности всех будущих God buffs за Offerings.
- Базовый ZBT шаг длительности: +1 секунда за уровень.
- Покупка duration upgrade не меняет уже активный `buffActiveUntil`; новая длительность применяется только к последующим активациям.
- Добавлены runtime feature gates `GOD_AUTO_ACTIVATION`, `GOD_PERMANENT_BUFF_DURATION`, `GOD_SECONDARY_BUFFS`, `GOD_RESET_PRESERVATION`.
- Gates по умолчанию data-driven и могут включаться без изменения Java gameplay core.

## Mastery Reset и persistence

- God run progression хранится отдельно от постоянного God meta-state.
- Обычный Mastery Reset по умолчанию полностью очищает God unlock/level/charge/buff/cooldown run-state.
- `Offerings`, permanent duration level и automation/activation preferences переживают Mastery Reset.
- При включённом `GOD_RESET_PRESERVATION` предусмотрен hook для полного сохранения God progression.
- Mongo persistence обратно совместим с v2.7 save-документами: отсутствие God state безопасно создаёт default state без миграционного разрушения старых данных.

## Server authority, events и UI

- Unlock, upgrade, Worship-click, automation preferences и duration purchase обрабатываются сервером; клиент отправляет только intent.
- God network использует новые packet discriminators `19` и `20` без изменения существующих IDs.
- Mutation requests защищены monotonic nonce/replay guard; Worship-click дополнительно ограничен server-side rate limiter.
- Factual God actions публикуются в общий `GameplayEvent` layer для Quest и будущих систем: unlock, upgrade, charge click, cooldown reduction, buff activate/expire, Auto Worship spend, Offerings earned/spent и linked activation.
- Добавлен функциональный God Worship UI: пять God rows, level/state, charge, buff/cooldown timers, costs, Worship/Unlock/Upgrade, Auto Worship, activation mode/link и глобальные Offerings/duration controls.
- UI остаётся функциональным structured skeleton; финальный визуальный polish не входит в v2.8.0.

## Balance Core и проверки

- Добавлен bundled overlay `balance/v2.8.0-god-worship.json` с canonical lowercase IDs.
- Все gameplay-числа God Worship, resource routing, rates, costs, durations, cooldowns, feature gates и effect channels читаются из Balance Core policy.
- Regression coverage проверяет economy, lifecycle, offline settlement, menu-only passive charge, manual final step, linked propagation, not-ready linked Gods, cycle safety, permanent-duration snapshot, reset/default preservation, secondary gates, same-channel additive stacking, future effectiveness hook, factual event uniqueness, migration и network guards.
- Release CI проверяет Java 8 clean build/tests, architecture/resource contracts, version consistency и содержимое итогового JAR.
