# RE:volution Mod v1.5.1

## Назначение релиза

`v1.5.1` - точечный hotfix после `v1.5.0`, исправляющий падение игрока при входе в состояние полностью закрытой текущей ступени purchase progression рун.

Баланс и ZBT snapshot из `v1.5.0` не перебалансируются и не расширяются этим релизом.

## Исправление complete purchase-stage

Для factual `RuneCollectionProgression` допустимо завершённое состояние текущей ступени, где `coveredCount = 26` и `isComplete() = true`.

Ранее `PlayerStatsSyncService` безусловно пытался вычислить следующую цену покупки через purchase curve. Для полного состояния `26/26` это приводило к обращению к TABLE curve с `lowerProgress = 26`, хотя 26-точечная таблица определена только для индексов `0..25`.

`v1.5.1` меняет sync-контракт так, что для `progression.isComplete()` следующая обычная purchase цена не вычисляется, а `purchaseUnitCost` передаётся как `0`.

Важно:

- индекс `26` не clamp-ится к `25`;
- несуществующая 27-я точка purchase curve не вычисляется;
- factual nested progression остаётся источником истины;
- completed state не превращается в фиктивную возможность ещё одной покупки.

## Regression coverage

Добавлены проверки для граничных состояний:

- полный purchase-stage `26/26`;
- завершённый nested cycle с `25` рун текущего lower rank и `1` руной higher rank;
- stats sync в этих состояниях не обращается к purchase curve за пределами `0..25`.

Фикс также подтверждён на DEV runtime на реальном профиле, на котором до hotfix вход падал с `TABLE curve has no value for index 26`.

## Что не меняется

- ZBT Draft balance snapshot остаётся тем же, что в `v1.5.0`.
- Purchase base curve, pressure `1.15 ^ higherRuneCount`, duplicate formula, enhancement и rank-up curves не меняются.
- Rank 4 не добавляется.
- Mongo schema не меняется.
- Balance Core schema version остаётся `1`.
- Mob identity, world geometry, population и visual assets не меняются.
