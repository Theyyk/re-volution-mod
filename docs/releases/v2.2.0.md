# RE:volution Mod v2.2.0

## Назначение релиза

`v2.2.0` подтверждает, что Prestige Foundation из `v2.1.0` действительно является generic-системой, а не реализацией, привязанной к одной ветке `CLICK`.

В релизе полностью подключены текущие Prestige branches:

- `CLICK`;
- `POISON`;
- `COINS`;
- `RUNE_RESOURCES`;
- `ALL_DAMAGE`.

Числа Prestige по-прежнему имеют статус **ZBT Draft**, не Final. Основная цель версии - gameplay wiring, архитектурная расширяемость и server-authoritative источники прогресса.

## Generic gameplay event boundary

Между gameplay-системами и Prestige добавлена нейтральная граница подтверждённых игровых фактов.

Combat и reward/resource systems публикуют только уже подтверждённый результат:

- фактически нанесённый damage с metadata источника;
- фактически выданный earned resource.

Prestige не пересчитывает combat, DPS, reward или текущий balance. Отдельный router сопоставляет подтверждённое событие с data-driven `ProgressSource` активной Prestige branch.

Damage metadata не ограничена бинарной моделью `CLICK vs POISON`. Контракт уже содержит расширяемые типы для будущих `FIRE`, `ICE`, `LIGHTNING`, `PET`, `ARTIFACT` и других источников.

## CLICK

`CLICK` остаётся regression baseline из `v2.1.0`.

Прогресс начисляется только по фактически снятому HP managed-моба. Poison damage в `CLICK` не попадает. Overkill не увеличивает progress сверх реально снятого HP.

Существующие rank thresholds и click effects сохранены без изменения поведения Foundation.

## POISON

`POISON` подключён к существующему server-side poison damage path.

Prestige получает уже подтверждённый damage после фактического изменения HP цели и не пересчитывает Poison DPS самостоятельно.

Для AoE каждый target создаёт собственный подтверждённый damage result через существующий combat path. Click и другие source types не увеличивают `POISON` progress.

Ветка получила реальный `POISON_DAMAGE_MULTIPLIER` через общий Effect Resolver.

## COINS

`COINS` использует контракт:

`progress = coins actually earned`.

Текущий balance не является источником прогресса. Поэтому:

- earned reward увеличивает progress;
- spending не уменьшает progress;
- загрузка balance не создаёт progress;
- прямой set/admin adjustment не создаёт progress.

Reward multiplier ветки применяется до persistence, после чего в Prestige публикуется точная фактически выданная сумма.

## RUNE_RESOURCES

`RUNE_RESOURCES` подключён к фактическим выдачам:

- `rune_dust`;
- `rune_shards`;
- `rune_cores`.

Resource weights заданы через data-driven mapping. Текущие веса являются ZBT Draft и могут быть изменены без замены Prestige lifecycle.

Ветка получила общий `RUNE_RESOURCE_REWARD_MULTIPLIER` через Effect Resolver.

## ALL_DAMAGE

`ALL_DAMAGE` принимает каждый подтверждённый player damage event независимо от его source metadata.

На текущем gameplay это подтверждено для `CLICK` и `POISON`; архитектурный contract также принимает будущие damage sources без изменения `ALL_DAMAGE` engine.

Один factual damage instance публикуется один раз и маршрутизируется один раз, поэтому отдельного вторичного суммирования CLICK/POISON внутри `ALL_DAMAGE` нет.

Ветка получила `ALL_DAMAGE_MULTIPLIER`, который композируется с source-specific damage multiplier.

## Generic branch lifecycle

Все branches используют один и тот же цикл:

`select -> run -> confirmed progress -> levels -> ranks -> effects -> reset preview -> confirm -> historical best -> meta-levels -> run wipe -> persistence`.

Branch-specific код ограничен definition/source/effect configuration. Отдельных `ClickPrestigeService`, `PoisonPrestigeService`, `CoinsPrestigeService` и аналогичных engines нет.

Только active branch получает run progression. Permanent state остальных веток не изменяется.

## Effect Resolver

Effect Resolver расширен следующими stats:

- `CLICK_DAMAGE_MULTIPLIER`;
- `POISON_DAMAGE_MULTIPLIER`;
- `ALL_DAMAGE_MULTIPLIER`;
- `COIN_REWARD_MULTIPLIER`;
- `RUNE_RESOURCE_REWARD_MULTIPLIER`.

Prestige contributions сохраняют идентифицируемый origin с branch, runId и rank для run-scoped effects либо branch для permanent effects.

При reset исчезают только run-scoped эффекты завершённого Prestige run; Rune и другие системы не затрагиваются.

## Persistence и reset regression

Prestige persistence shape не изменён и остаётся на `schemaVersion = 1`.

Existing `v2.1.0` CLICK state загружается без migration/reset-default.

Сохраняются существующие reset contracts:

- Ordinary -> Normal;
- Improved -> Normal;
- Advanced -> preserve;
- Enhancement -> preserve;
- Crystals -> never reset.

Historical best и rank meta-levels независимы для каждой branch. Stale/duplicate reset protection через `runId` сохранён.

## Functional interface

Сохраняются команды:

- `/prestige branches`;
- `/prestige select <branch>`;
- `/prestige status`;
- `/prestige reset`;
- `/prestige reset confirm <runId>`;
- `/prestige diagnose`.

`branches`, `status` и `diagnose` дополнительно показывают active progress source для тестирования wiring.

Полноценный Prestige GUI в этот релиз не входит.

## Tests

Добавлены автоматические проверки:

- source isolation CLICK/POISON;
- exact-once routing ALL_DAMAGE;
- future damage sources через общий metadata contract;
- earned coins vs balance/spending/admin mutation;
- rune-resource routing;
- reward effect -> actual granted amount -> progress;
- inactive branch isolation;
- одинаковый rank/effect/reset lifecycle новых branches;
- independent historical best;
- existing v2.1.0 CLICK/reset regression.

## Out of scope

В `v2.2.0` не входят:

- full Prestige GUI;
- final Prestige balance;
- Mastery Quest;
- generic Quest System;
- full Run Exchange;
- Pet System;
- Forge / Artifacts;
- visual polish.

Следующий ожидаемый крупный gameplay batch после подтверждения стабильности этой версии - **Pet Foundation**.
