# v1.4.1 — Balance Core

## Scope

`v1.4.1` introduces the canonical balance foundation while intentionally preserving the gameplay behavior released in `v1.4.0`.

### Added

- Immutable canonical balance definitions with `balanceSchemaVersion: 1`.
- JSON parser for canonical balance data.
- Strict semantic validation before activation.
- Deterministic `FIXED`, `TABLE`, `FORMULA`, and `PIECEWISE` curve evaluation.
- `BigDecimal` balance values without narrowing to `int`, `long`, or `double` in the new balance core.
- Deterministic canonical JSON and SHA-256 balance revision.
- Atomic `prepare` / `activate` service semantics: invalid configs never replace the previous active snapshot.
- JUnit regression coverage for parser, validation, curve math, hashing, large values, and atomic activation.

### Compatibility

- Existing `RuneEconomyConfig` remains the gameplay source in this release.
- Rune purchase, duplicate, enhancement, rank-up, combat effects, mob HP/rewards/population and Admin stage editing behavior are unchanged.
- No player-save or Mongo schema migration is introduced.
- No balance file is loaded automatically during server bootstrap yet.
- No Google Sheets or live Google API integration is introduced.

## Next

`v1.4.2` will migrate Rune Purchase and duplicate rewards onto the canonical balance layer after this core contract is accepted.
