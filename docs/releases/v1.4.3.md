# RE:volution Mod v1.4.3

`v1.4.3` переводит Rune Enhancement на canonical Balance Layer и закрепляет правило, что цена усиления зависит от общего прогресса коллекции, а не от случайно выбранного слота.

## Добавлено

- `RuneEnhancementBalanceService` — rune-domain адаптер над Balance Core для ресурса, targeting и cost curve усилений.
- `RuneEnhancementPlanningService` — чистый слой планирования, отделяющий глобальный расчёт стоимости от RNG-выбора слотов.
- Targeting-режимы `ALL_SLOTS` и `OWNED_ONLY`.
- Canonical ключи `runes.<status>.enhancement.resource`, `runes.<status>.enhancement.targeting` и `runes.<status>.enhancement.cost`.
- JUnit-покрытие глобальной стоимости, bulk-последовательности, targeting и невалидной конфигурации.
- Release guard: version metadata, стабильная версия README, ссылка README на текущий release contract и stable tag должны совпадать.

## Изменено

- `TotalEnhancementLevel` определяется как сумма `enhancementLevel` всех slots коллекции.
- Стоимость bulk-усиления считается последовательными глобальными шагами от текущего `TotalEnhancementLevel`.
- RNG выбирает только допустимый target slot и больше не влияет на цену операции.
- Existing enhancement packet остаётся wire-compatible: каждая строка получает одинаковые collection-global bulk costs.
- Admin reset/sync усилений проходит через единый `RuneSyncService`, поэтому Admin path не обходит активный Balance Layer.

## Текущий baseline

Для Poison намеренно сохранены существующие placeholder-значения:

- ресурс усиления — `rune_dust`;
- targeting — `ALL_SLOTS`;
- стоимость одного глобального enhancement step — `10 rune_dust`;
- enhancement power step остаётся `0.1` и пока не переносится в этот релиз.

Таким образом `v1.4.3` меняет источник и правило расчёта экономики, но не проводит финальный баланс чисел.

## Совместимость

- Mongo/player schema migration не требуется.
- Existing persisted enhancement levels сохраняются и сразу участвуют в `TotalEnhancementLevel`.
- Network wire format не меняется.
- Rank-up не входит в `v1.4.3`; его migration остаётся отдельным этапом `v1.4.4`.
- Rune effects, mob balance, Admin Preview/Apply и export tooling также остаются последующими этапами.

## Проверки

Release candidate должен пройти полный Gradle build, JUnit/standalone regression tests, architecture/security guards, packaged-resource verification и version/README consistency validation. Stable tag создаётся только после успешного exact-main CI.
