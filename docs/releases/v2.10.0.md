# RE:volution v2.10.0

## Основное

`v2.10.0` добавляет постоянную server-authoritative **Achievements System** поверх существующего factual gameplay event layer. Прогресс достижений, claimed stages, Achievement Points, lifetime-unique наборы и hidden reveal state не являются run-scoped и не сбрасываются Mastery Reset.

Основной цикл:

`factual gameplay event -> permanent progress -> stage completed -> ручной Claim -> rewards + Achievement Points -> Achievement Level -> permanent economy bonus`.

Клиент не задаёт factual progress, completed state, rewards или Achievement Points. Он отправляет только intent Claim/Share/Sync, а сервер повторно проверяет состояние и формирует UI/chat payload.

## Stages и Claim

- Одно Achievement содержит произвольное количество последовательных stages.
- Stage targets обязаны строго возрастать; UI использует Roman labels, но модель не ограничена I-V.
- Достижение stage по progress не выдаёт награду автоматически.
- Claim разрешён только для следующего последовательного stage.
- C2S Claim включает `achievementId + expectedStageIndex`, поэтому повтор старого Claim не может случайно забрать следующий stage.
- Achievement Points начисляются только при успешном Claim.
- Persistent Mongo Claim выполняется одной atomic update operation для claimed stage, Points, Crystals, Aura Keys, Offerings и receipt.

## Категории и factual источники

В Balance Core заведены категории:

- Damage;
- Resources;
- Mastery;
- Pets;
- Runes;
- Kills;
- Locations;
- Auras.

Damage считается через единый confirmed-damage boundary. Поддерживаются `CLICK`, `POISON`, `BURNING`, `BLEEDING`, `CURSE`, `WITHER`, `DECAY` и отдельный total counter. Один damage fact увеличивает total и ровно один channel counter без повторного generic учёта.

Resource lifetime progress использует только authoritative earned grants для Coins, Rune Dust, Rune Shards и Rune Cores. Spending и административная установка баланса не считаются earned progress.

Mastery branches, Pets и Locations используют permanent unique sets. Повторный выбор того же branch, повторное получение того же Pet или повторное посещение Location не увеличивает lifetime unique counter.

Rune category содержит factual Rune Awakening progression. Kills используют total mob kills и stable `spawnKey` для specific/boss filtering. Boss IDs задаются Balance Core и не выводятся из display name.

Aura Achievements используют только `AURA_DROPPED_FROM_CHEST`. Craft/dismantle не подменяют chest-drop progression. Rarity filters работают по factual rarity metadata.

## Hidden Achievements

Hidden Achievement до первого factual completion не раскрывает клиенту настоящий descriptive id или детали. Snapshot содержит только технический placeholder `hidden:N`, `???` и категорию `HIDDEN`.

После первого пересечения stage target сервер permanently сохраняет reveal и публикует `ACHIEVEMENT_REVEALED`. Reveal переживает logout/restart и не сбрасывается Mastery Reset.

## Rewards

Stage reward может содержать:

- Crystals;
- Offerings;
- Aura Keys;
- Achievement Points.

Используются существующие кошельки:

- Crystals -> top-level player Crystal balance;
- Aura Keys -> `resources.aura_key`;
- Offerings -> `godWorshipPersistent.offerings`.

Persistent Claim закрывает crash-window одним Mongo pipeline update. Claim receipt дополнительно не позволяет повторно применить один stage.

## Achievement Points, Level и economy bonus

Achievement Level не хранится как второй источник истины: он каждый раз выводится из постоянных Achievement Points через Balance Core curve.

Level curve использует TABLE seed + `tail_growth`, поэтому progression продолжается после последней явно заданной точки и не имеет фиксированного Java hard cap.

Для Coins, Rune Dust, Rune Shards и Rune Cores применяется один и тот же permanent Achievement reward multiplier.

Resource pipeline:

`base reward -> normal gameplay modifiers -> Achievement multiplier -> Aura late multiplier -> persisted earned amount`.

Именно фактически сохранённая финальная сумма передаётся в earned-resource Achievement progress.

## Persistence и миграция v2.9

Achievement state хранится обратно-совместимо внутри существующего player document как `achievementState`, schema version 1.

Сохраняются:

- per-achievement progress;
- highest claimed stage;
- Achievement Points;
- ever-selected Mastery branch IDs;
- ever-obtained Pet IDs;
- visited Location IDs;
- permanently revealed hidden Achievement IDs.

При первом входе старого v2.9 player без `achievementState` восстанавливаются только факты, которые можно доказать существующим persistent state:

- `auraState.totalChestAuraDrops` -> общий Aura chest-drop progress;
- текущие/persistent Pets из `petSystem.pets` и текущие `purchasedPetIds` -> lower-bound Pet ownership history;
- active Mastery branch и branches с factual saved/meta progress -> lower-bound Mastery branch history.

Damage, resource earnings, Location history и rarity-specific historic Aura drops не угадываются и начинают с нуля, если v2.9 не хранила достаточный factual источник.

High-frequency progress держится в server cache как dirty state и flushится периодически, при logout и shutdown; Mongo write на каждый damage tick не выполняется.

## Network и replay protection

Achievements используют discriminators:

- `23` - C2S Achievement action;
- `24` - S2C server-authored snapshot.

Claim и Share защищены monotonic nonce guard. Duplicate/lower nonce отклоняется. Limiter очищается при logout и shutdown. Sync является read-only и не требует nonce.

## Share

Share формируется сервером из permanent factual state.

Chat содержит тег вида `[Achievement: <name> <roman-stage>]`, progress/target и hover с completed/claimed state. Hidden Achievement нельзя поделиться до server-side reveal.

## UI

Добавлена функциональная вкладка `Achievements` рядом с существующим Rune UI без переписывания Rune layout.

Экран показывает:

- категории;
- current stage;
- progress / target;
- completed и claimed stage history;
- Crystals / Offerings / Aura Key / AP reward;
- Claim;
- Share;
- total Achievement Points;
- Achievement Level;
- permanent economy bonus;
- next level threshold;
- hidden placeholders до reveal.

UI остаётся functional-first skeleton; финальный visual polish не является scope v2.10.0.

## Balance Core

Добавлен overlay `balance/v2.10.0-achievements.json`.

Через него задаются:

- список Achievement definitions;
- event type;
- metadata filters;
- hidden flag;
- произвольные stage targets;
- rewards каждого stage;
- boss stable-id list;
- Achievement Level thresholds;
- economy bonus curve.

Текущие числовые значения помечены `achievement.zbt_status = draft` и остаются **ZBT Draft**. Stable в v2.10.0 - архитектура, persistence, server authority и data-driven contract, а не финальные production thresholds/rewards.

## Scope

В v2.10.0 не добавлены:

- Quest Achievements;
- God Worship Achievements;
- Forge gameplay Achievements;
- финальный production balance;
- финальный visual polish.

Для будущей Forge-интеграции добавлен только factual event contract `FORGE_ITEM_CRAFTED`.

## Проверки

Regression coverage включает:

- total/channel damage без double count;
- несколько completed stages до первого Claim;
- strict sequential Claim и replay старого stage;
- claim-only Achievement Points;
- lifetime unique Mastery/Pet/Location state;
- hidden reveal persistence;
- atomic persistent Claim path;
- stable boss-id filters;
- unlimited Balance tail для Level/bonus;
- v2.9 factual migration;
- Mongo codec exact large-number progress;
- packet round trips;
- request replay limiter;
- architecture discriminators `23/24`;
- resource asset contract;
- полный существующий regression suite проекта.
