# RE:volution Mod v1.3.1

v1.3.1 фиксирует архитектурный baseline перед CR по world/realm/location/fixed mobs. Игровая механика и схема хранения сохранены; цель версии — привести границы ответственности, lifecycle и проверки к состоянию, пригодному для дальнейших крупных изменений.

## Изменения

- Корень Java-пакета содержит только Forge bootstrap. Lifecycle, физические стороны и граф зависимостей разделены.
- Вместо больших статических менеджеров используются экземпляры сервисов и порты репозиториев. Mongo-клиент имеет одного владельца и закрывается при остановке.
- Разделены определения, временное состояние, сохранённые проекции, правила, хранение, транспорт и интерфейс. Forge event objects остаются в адаптерах.
- Покупка, усиление и пробуждение вынесены из packet handler; admin-операции и сценарии команд делегируют сервисам. Wire DTO не читают экономику и конфигурацию.
- Клиентские lifecycle/network/input adapters вынесены в отдельные пакеты; доступ к внутреннему GUI сохранён через узкие `ClientBootstrap` / `ClientUiBridge`, без массового расширения `public`.
- Forge-адаптеры мобов и входа игрока сгруппированы в `mob.event` и `player.event`.
- Удалены неиспользуемый `ServerInit` и незарегистрированный `BalancePacket`.
- Regression-задачи объявлены общей таблицей; абсолютный `org.gradle.java.home` удалён. JDK выбирается через `JAVA_HOME` или параметры пользователя.
- Усилены архитектурные и package/JAR guards; добавлены проверки Mongo schema, wire bytes, сервисных контрактов и whitelist JSON. Пакеты тестов следуют production-структуре.
- Исправлена совместимость GUI с ранней Java 8, включая Java 8u51: mutating-вызовы типизированных NIO buffer выполняются через `java.nio.Buffer`, а CI проверяет весь production-код на возврат несовместимого паттерна.
- [Архитектура](../architecture.md) задаёт контракт следующих CR. Механика realms/fixed mobs в 1.3.1 не добавлена.

## Совместимость

Forge 1.12.2 / 14.23.5.2859, Java 8, формулы, экономика, action strings, IDs 0–7, канал `revolution:main`, Mongo schema, legacy read compatibility и optional-client protocol support сохранены. Набор ресурсов, пути, fallback и reload не менялись.

Проверка входа vanilla/no-mod клиента исключена из runtime acceptance 1.3.1 отдельным решением проекта. Это не меняет сам сохранённый optional-client protocol contract.

## Проверки

Автоматически выполнены `clean build`, 21 Java regression runner, архитектурные проверки и негативные guard-тесты. Mongo contract test проверяет маппинги/driver calls без подключения к живой MongoDB; wire goldens покрывают все восемь зарегистрированных DTO.

Финальный feature HEAD `a7aefc9577f01fd45cd980e0e5922a65563cbb27` прошёл CI и runtime acceptance. В runtime подтверждены GUI `C`/`O`, admin/whitelist, покупки и усиления рун, пробуждение/оплата/сохранение, x100/autoclicker, combat effects, managed mobs и награды, большие значения, unload/load и resource-pack reload. После обычного merge PR #69 commit `af7da61ac4f29b45392fbbd1c678a1127aab0ab3` прошёл post-merge CI в `develop`.

## Загрузка

После публикации используйте `RE-volution-1.3.1.jar` на сервере и клиентах с модом. Набор ресурсов поставляется отдельно прежним способом. Тег и GitHub Release создаются только release workflow после принятия release commit.
