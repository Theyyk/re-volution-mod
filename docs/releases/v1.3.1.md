# RE:volution Mod v1.3.1

Архитектурный baseline перед CR по world/realm/location/fixed mobs. Версия готовится к review в `develop`; этот файл не подтверждает публикацию или runtime-приёмку.

## Изменения

- Корень Java-пакета содержит только Forge bootstrap. Lifecycle, физические стороны и граф зависимостей разделены.
- Вместо больших статических менеджеров используются экземпляры сервисов и порты репозиториев. Mongo-клиент имеет одного владельца и закрывается при остановке.
- Разделены определения, временное состояние, сохранённые проекции, правила, хранение, транспорт и интерфейс. Forge event objects остаются в адаптерах.
- Покупка, усиление и пробуждение вынесены из packet handler; admin-операции и сценарии команд делегируют сервисам. Wire DTO не читают экономику и конфигурацию.
- Удалены неиспользуемый `ServerInit` и незарегистрированный `BalancePacket`.
- Regression-задачи объявлены общей таблицей; абсолютный `org.gradle.java.home` удалён. JDK выбирается через `JAVA_HOME` или параметры пользователя.
- Усилены архитектурные и package/JAR guards; добавлены проверки Mongo schema, wire bytes, сервисных контрактов и whitelist JSON. Пакеты тестов следуют production-структуре.
- [Архитектура](../architecture.md) задаёт контракт следующих CR. Механика realms/fixed mobs не добавлена.

## Совместимость

Forge 1.12.2 / 14.23.5.2859, Java 8, формулы, экономика, action strings, IDs 0–7, канал `revolution:main`, Mongo schema, legacy read compatibility и optional-client сохранены. Набор ресурсов, пути, fallback и reload не менялись.

## Проверки

Локально выполнены `clean build` на Java 8, 21 Java regression runner, архитектурные проверки и негативные тесты guards. Mongo contract test проверяет маппинги/driver calls без подключения к живой MongoDB; wire goldens покрывают все восемь зарегистрированных DTO.

GitHub Actions проверяется на текущем SHA PR; актуальный статус находится в PR. Runtime Minecraft с модом/без мода, реальные Mongo-данные, chunk unload/restart, GUI и resource-pack reload требуется пройти по [checklist](../development.md#runtime-проверка-131). Результаты прежнего релиза не считаются проверкой нового JAR.

## Загрузка

После принятия и публикации используйте `RE-volution-1.3.1.jar` на сервере и клиентах с модом. Набор ресурсов поставляется отдельно прежним способом. Ветка не создаёт тег и не публикует релиз без release workflow.
