# RE:volution Mod v2.1.0

## Назначение релиза

`v2.1.0` добавляет фундамент системы Prestige поверх существующей игровой архитектуры. Релиз фиксирует механику циклов Prestige, сохранение постоянного прогресса, reset-policy и первую рабочую ветку `CLICK`.

Числа Prestige имеют статус ZBT Draft, не Final. Этот релиз фиксирует архитектурный и игровой контракт системы, а не окончательный баланс.

## Prestige Foundation

- Prestige построен как расширяемая система веток с отдельным run-state и permanent-state.
- Активный цикл имеет собственный `runId`, выбранную ветку, прогресс, уровень, достигнутые ранги и run-scoped currency.
- Постоянное состояние хранит лучший сохранённый результат по ветке, meta-level рангов и фундамент ограничений/мастерства.
- Состояние Prestige сохраняется в MongoDB.
- Stale и повторные reset-запросы защищены через `runId`, чтобы один цикл нельзя было применить повторно.

## Ветка CLICK

`CLICK` является первой полностью подключённой reference-веткой Prestige.

Прогресс берётся из фактически нанесённого click damage по managed-мобам, а не из отдельного искусственного счётчика. Это сохраняет существующий server-authoritative combat path и позволяет Prestige использовать фактический игровой результат.

Достигнутые ранги обновляются автоматически по мере прогресса ветки.

## Эффекты

Добавлен общий effect-resolution слой, через который Prestige может влиять на игровые характеристики без жёсткой привязки combat-кода к одной системе прогрессии.

Foundation включает поддержку click-damage multiplier как первого эффекта и оставляет расширяемую границу для последующих источников и характеристик.

## Сброс Prestige

Reset выполняется централизованно и сначала может быть просмотрен через preview.

После подтверждённого reset:

- текущий результат сравнивается с историческим лучшим результатом;
- permanent progression обновляется только по правилам Prestige;
- повторное применение того же `runId` не выдаёт результат повторно;
- активный run завершается, после чего игрок может начать новый цикл.

Rune-policy при Prestige reset:

- **Обычная** и **Улучшенная** руны сбрасываются по рангу;
- **Продвинутая** сохраняется;
- уровни усиления `+N` сохраняются независимо от изменения ранга;
- `crystals` не сбрасываются и не расходуются этим механизмом.

## Интерфейс Foundation

Добавлена функциональная команда `/prestige` без финального визуального полиша.

Она позволяет:

- посмотреть доступные ветки;
- выбрать ветку и начать run;
- посмотреть состояние активного run;
- получить preview reset;
- подтвердить reset через `runId`;
- использовать admin diagnostics для проверки run/permanent-state.

Это намеренно mechanics-first интерфейс, который можно заменить полноценным GUI без изменения серверного контракта Prestige.

## Balance Core

Prestige использует существующую границу Balance Core. Текущие значения являются placeholder/ZBT Draft и не считаются Final.

Foundation не требует отдельного параллельного источника баланса и рассчитан на дальнейшую настройку значений через существующий data-driven подход.

## Что не меняется

- Базовая Realm и Location/stage архитектура не заменяется.
- Existing managed-mob progression и contribution остаются server-authoritative.
- Rune enhancement policy после `+50` не меняется.
- Обычный Rune Rank Revert не заменяется Prestige reset и остаётся отдельной механикой.
- Баланс мобов, награды и текущие rune/economy значения этим релизом автоматически не ребалансируются.
- Числа Prestige остаются ZBT Draft до отдельной балансной проработки.
