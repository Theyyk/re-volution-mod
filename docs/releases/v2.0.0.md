# RE:volution Mod v2.0.0

## Назначение релиза

`v2.0.0` переводит проект в состояние ZBT-кандидата с RPG-oriented client UX вместо vanilla survival presentation.

Числа баланса остаются ZBT Draft, не Final. Релиз 2.0.0 фиксирует текущую реализацию систем и интерфейсов для проведения закрытого бета-тестирования.

## RPG Survival режим

Игрок в Survival используется как участник RPG-runtime, а не vanilla survival:

- player damage блокируется;
- разрушение блоков блокируется;
- vanilla player inventory не показывается через `E`, вместо него открывается главное меню RE:volution;
- vanilla hotbar, hearts, hunger и experience HUD скрыты;
- food level серверно удерживается заполненным, чтобы голод не заканчивался;
- Creative-администраторы не ограничиваются этим guard и сохраняют возможность строить.

## Управление и HUD

Основное меню перенесено на `E`. Конфликтующие vanilla bindings для Inventory и Advancements отключаются на клиенте, а vanilla attack cooldown indicator скрыт.

В правом нижнем углу отображаются компактные подсказки по актуальным RE:volution keybinds, включая меню, формат больших чисел и переход по локациям. Там же остаётся Realm-информация.

Vanilla survival HUD заменён минималистичным RPG HUD:

- снизу по центру отображаются основные ресурсы: coins, crystals, Пыль рун, Осколки рун и Ядра рун;
- слева сверху отображаются синхронизированные финальные значения click damage и poison damage в компактном формате;
- большие значения используют существующий LargeNumbers formatter.

Полоса HP managed-мобов визуально приглушена, чтобы меньше перекрывать игровой экран.

## Уведомления вместо системного chat-log

Системные RE:volution сообщения больше не должны засорять обычный чат. Для них используется отдельный notification feed:

- одновременно отображается до трёх сообщений;
- старые сообщения автоматически уходят;
- notification feed размещён справа и разведён с боевым HUD;
- обычный player chat не отключается.

## Экономика GUI

Кнопка покупки рун теперь учитывает фактический баланс монет.

Для bulk purchase `x1/x5/x10/x100` кнопка блокируется, если игроку не хватает монет на полную стоимость выбранного количества.

## Managed mobs и poison combat-stop

Существующая остановка managed-моба после прямого удара расширена на poison ticks. Каждый новый tick яда продлевает ту же combat pause и временно останавливает движение managed-моба, после чего обычное движение восстанавливается.

## Отображение наград

Player-facing reward labels используют общий каталог ресурсов вместо raw internal IDs:

- `rune_dust` → `Пыль рун`;
- `rune_shards` → `Осколки рун`;
- `rune_cores` → `Ядра рун`.

Внутренние resource IDs не меняются.

## Population и fixed placement

При изменении population через Control/Admin сохраняется контракт:

- `fixed = floor(population / 2)`;
- `random = ceil(population / 2)`;
- при нечётном population лишний моб всегда относится к `RANDOM_AREA`.

Новые `FIXED_POINT` больше не клонируют одну центральную координату. Их позиции рассчитываются по геометрии stage (`centerX`, `centerZ`, `radius`) и распределяются внутри зоны с разнесением между fixed-точками.

`RANDOM_AREA` продолжает выбирать случайную позицию при фактическом спавне.

## Что не меняется

- ZBT balance values остаются Draft, не Final.
- Rune purchase base curve, duplicate compensation, rank-up costs и enhancement policy не меняются этим релизом.
- Unlimited enhancement после +50 и TABLE tail `1.10` остаются как в v1.5.2.
- Rune Rank Revert policy не меняется.
- Location 1 HP/reward balance не меняется.
- Mongo schema и Balance Core schema version не меняются.
