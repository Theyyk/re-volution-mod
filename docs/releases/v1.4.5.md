# RE:volution Mod v1.4.5

`v1.4.5` переводит существующие параметры Rune Effects для Poison на canonical Balance Layer без изменения текущего gameplay baseline. Runtime эффекты больше не должны получать числовые значения из Java-hardcode, если параметр уже описан в активном balance snapshot.

## Добавлено

- `RuneEffectBalanceService` - rune-domain адаптер для чтения effect definitions из активного `BalanceService`.
- Canonical definitions для существующих Poison effect groups, tags, effect type и target selector.
- Rank-specific значения для текущих эффектов вместо общего Java scaling `NORMAL=1`, `IMPROVED=3`, `ADVANCED=9`.
- Индивидуальный enhancement step в canonical balance data.
- Data-driven параметры targeted power, proc chance/multiplier, rage multiplier/duration/max stacks и reward bonus.
- Regression coverage для bundled baseline и разрешения effect values через Balance Core.

## Изменено

- `RuneCombatService` получает effect power и enhancement step через Balance Core вместо локальных числовых констант.
- `RuneRewardBonusService` использует тот же активный balance snapshot, что и остальная rune economy.
- Server composition использует общий `BalanceService`, чтобы экономика и эффекты не расходились по независимым snapshots.
- Slot-to-target mapping и существующие Poison mechanics сохранены по текущему контракту, но их параметры теперь разрешаются через canonical definitions.

## Текущий baseline

Миграция не добавляет новую механику и сохраняет существующие значения Poison, включая:

- rank scaling, эквивалентный прежним значениям `1 / 3 / 9`;
- enhancement step `0.1`;
- существующие targeted-power связи;
- hidden-strike proc baseline `15%` и multiplier `x2`;
- rage baseline `x2`, duration `5s`, max stacks `1`;
- существующие reward-bonus параметры.

Точные значения теперь находятся в `src/main/resources/balance/default-balance.json` и являются частью canonical balance snapshot.

## Совместимость

- Mongo/player schema migration не требуется.
- Network wire format не меняется.
- Ранги и enhancement persistence не меняются.
- Purchase, duplicate, enhancement и rank-up economy продолжают использовать тот же Balance Core.
- Player-controlled Rune Rank Revert не входит в `v1.4.5`; он остаётся отдельной запланированной механикой `v1.4.9`.
- Следующий этап после stable `v1.4.5` - `v1.4.6 Mob Balance`.

## Проверки

Release candidate должен пройти полный Gradle build, JUnit/standalone regression tests, architecture/security guards, packaged-resource verification и version/README consistency validation. Stable tag создаётся только после успешного exact-main CI.
