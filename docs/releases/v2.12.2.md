# v2.12.2 — Pets, Aura, Mastery и Location Stabilization

**Статус:** Release candidate до подтверждения exact-head CI, DEV Minecraft Release QA, promotion в main и GitHub Release. PROD deployment не разрешён.

## Относительно v2.12.1

- Pets Context Slots: карточка, выделенные слоты, Awakening и серверные снимки.
- Aura Foundation: Aura Slot, состояния, equip/unequip, crafting, HUD и разблокировка.
- Mastery: отдельный интерфейс Y, Run Foundation, пять направлений, постоянные ранги, Mastery Tier и Premium Preserve для Ordinary/Mastery Reset.
- Location: обычное открытие этапов без Mastery Run, сохранение открытых этапов при начале Run, сброс только временного прогресса при успешном Reset и возврат на первый настроенный этап первой локации.
- Обновлены HUD, background blur, обработка GUI-модалок, синхронизация и регрессионные тесты.

## Инварианты данных

- Текущий цикл: `prestige.locationCycleUnlockedStages`. Запуск Mastery Run не очищает его.
- Исторические поля `mob_progression.unlockedSlots`, `legacyRunSlots` и `permanentSlots` сохраняются; исторические записи нельзя массово классифицировать или удалять в составе release.
- `pendingLocationReturnRunId` обеспечивает восстановление отложенного возврата после reconnect.
- Повторный Reset с прежним Run ID не должен повторять действие; Premium wallet должен списываться не более одного раза.
- Стандартные руны коллекций 1–7: ORDINARY/IMPROVED удаляются при обычной non-premium политике, ADVANCED+ и их upgrades остаются; Unique Runes не затрагиваются.

## MongoDB compatibility и rollback

- Прочтение устаревших записей новым кодом, запись, повторная миграция, reconnect, DEV restart и duplicate requests являются обязательными gate до Stable.
- Наличие нового embedded `prestige.schemaVersion = 3` не доказывает безопасность обратного чтения старым v2.12.1 бинарником.
- До будущего PROD rollout обязателен согласованный консистентный backup MongoDB + world, пробное восстановление на изолированной среде, инвентаризация версий клиент/сервер и план возврата обоих компонентов.
- Если обратная совместимость не доказана, не запускать старый сервер поверх уже обновлённых данных. PROD rollback тогда означает restore консистентного snapshot.
- При подтверждённом риске потери поддерживаемых сохранений Stable публикация блокируется, а не ограничивается предупреждением.

## Admin diagnostics

- `/stage access-audit <player>` — диагностика происхождения доступа.
- `/stage classify-legacy-run <player>` — preview адресной классификации.
- `/stage classify-legacy-run <player> confirm` — подтверждённая адресная классификация.
- Никакой автоматической массовой миграции старых `unlockedSlots`.
