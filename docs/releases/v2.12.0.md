# v2.12.0 - Mechanic Unlock System

## Главное

В версии `v2.12.0` добавлена центральная permanent-система открытия игровых механик через прогресс обычных Rune Collections.

Новый progression использует только фактическое состояние Standard Rune Collections и хранит исторический максимум отдельно по rarity. Повторный сбор уже достигнутого уровня после reset, rollback или Awakening-переходов не позволяет повторно фармить unlock progress.

## Mechanic Unlocks

- В начале progression доступны Standard Rune Collections и отдельная панель `Mechanic Unlocks`.
- Основные системы отображаются как locked согласно Balance Core и открываются только после ручного нажатия `Unlock`.
- Достижение requirement означает только `eligible`; автоматического открытия нет.
- Unlock requirements ничего не списывают и не являются валютой.
- Обычный gameplay может только открывать механику; обратный lock доступен только admin/debug-инструментам.
- Persistent unlock state переживает logout, restart и Mastery Reset.

## Rune progression

- Source of truth: `maxRuneProgressByRarity` для `COMMON`, `IMPROVED`, `ADVANCED`, `MYTHIC` и зарезервированного `ANCIENT`.
- Historical maximum обновляется только при фактическом превышении старого максимума.
- Duplicate/result, который не был реально добавлен как Rune, не увеличивает progress.
- Awakening-generated Rune следующей rarity учитывается после фактического изменения Rune state.
- Unique Rune Collections, Crystal/Daily/Offerings Unique Runes в этот progression не входят.

## Доступ к системам

Balance Core управляет unlock definitions для:

- Arts / Mastery;
- Run Exchange;
- God Worship;
- Aura System;
- Achievements;
- Unique Rune Collections;
- внутренних God mechanics: Auto Worship, Permanent Duration, Secondary Buffs и Reset Preservation.

Child mechanics скрыты до фактического ручного unlock родительской системы. Server-side gates закрывают прямые packets, команды, hotkeys и passive modifier paths, не удаляя сохранённые данные закрытой системы.

Achievement factual lifetime tracking продолжает работать в фоне до открытия player-facing access.

## Интерфейс и безопасность

- Панель показывает requirement, текущий historical progress, locked/unlocked/ready state и кнопку `Unlock`.
- Unlock tab подсвечивается, пока существует хотя бы одна visible eligible mechanic.
- Popup/toast/chat notification при достижении requirement не добавлялись.
- Unlock intent защищён monotonic nonce replay guard.
- Hidden child details не отправляются клиенту до разрешённой visibility.

## Admin / debug

Добавлена команда:

`/mechanicunlock status <player>|unlock <player> <id>|lock <player> <id>|clear <player> <id>|setprogress <player> <rarity> <count>`

Force lock блокирует доступ, но не уничтожает persistent mechanic data. После снятия override существующее состояние снова доступно.

## Balance

Initial thresholds находятся в `balance/v2.12.0-mechanic-unlocks.json` и имеют статус **ZBT Draft**. Они не считаются Final Balance.

## Совместимость

Сохранены существующие semantics Standard Rune Collections, Rune Awakening и reset/revert, Unique Rune Collections, Achievements background progress, Aura, God Worship, Run Exchange, Mastery, Pets, Quests, resources, Balance Core, Mongo persistence и network replay guards.
