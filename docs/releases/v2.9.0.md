# RE:volution v2.9.0

## Основное

`v2.9.0` добавляет полноценную постоянную **Aura System** поверх существующего gameplay. Aura не имеет уровней или XP, хранится независимо от run-scoped progression и может быть потеряна только при явном craft/dismantle игроком.

Основной цикл релиза:

`Aura Key -> Aura Chest -> случайная Aura -> постоянная коллекция -> equip одной Aura -> craft/dismantle -> поздний Aura modifier layer`.

Реализация server-authoritative: клиент отправляет только намерение, а rarity, rolls, seed, стоимость, количество результата и итоговые Aura instances определяются сервером.

## Aura Key и Aura Chest

- Добавлен постоянный ресурс `aura_key` с отображаемым именем `Ключ Ауры`.
- Один Aura Key расходуется на один независимый chest roll.
- Поддерживаются открытия `x1`, `x3`, `x5`, `x10`.
- Если ключей недостаточно, UI сначала показывает точное недостающее количество и полную стоимость в Crystals.
- Покупка недостающих ключей требует явного повторного подтверждения.
- Цена одного ключа и разрешённые количества открытия читаются из Balance Core.
- При недостатке Crystals операция завершается без открытия chest и без изменения Aura collection.
- Lifetime `totalChestOpens` и `totalChestAuraDrops` учитывают только реальные chest openings / `origin = CHEST`.

## Rarity и генерация Aura

Поддерживаются:

- `COMMON`
- `RARE`
- `EPIC`
- `LEGENDARY`
- `MYTHIC`

Любая включённая rarity может выпасть непосредственно из Aura Chest. Drop weights, количество rolls и диапазоны magnitude задаются Balance Core.

Каждая Aura instance сохраняет:

- `instanceId`;
- `rarity`;
- `origin` (`CHEST`, `CRAFT`, `DISMANTLE`);
- `generationSeed`;
- `rawRolls[]`;
- `aggregatedEffects`;
- `pinned`;
- время создания.

Generation seed вместе с активной конфигурацией Balance позволяет детерминированно воспроизвести generation path. Raw rolls сохраняются постоянно, а одинаковые effect rolls внутри одной Aura разрешены и аддитивно агрегируются.

Пример:

- raw: `CLICK +34%`, `CLICK +20%`, `POISON +17%`, `CLICK +8%`;
- aggregate: `CLICK +62%`, `POISON +17%`.

## Effect pool и поздний modifier layer

Aura pool поддерживает gameplay-эффекты для:

- CLICK;
- POISON;
- BURNING;
- BLEEDING;
- CURSE;
- WITHER;
- DECAY;
- ALL_DAMAGE;
- vulnerability/effectiveness;
- Coins;
- Rune Dust;
- Rune Shards;
- Rune Cores.

God-specific, Pet-specific и Offerings-specific progression не входят в Aura pool.

Damage pipeline для Aura работает как отдельный поздний слой:

`обычные gameplay effects -> GOD -> AURA -> final damage`.

Для одного damage event одновременно учитываются общий `ALL_DAMAGE` и channel-specific Aura effect. Resource rewards также проходят через обычные modifiers, затем через поздний Aura modifier и только после этого сохраняются как финальная награда.

## Collection, active Aura и pinning

- Коллекция Aura не ограничена по количеству.
- Одновременно активна максимум одна Aura.
- Нельзя напрямую заменить активную Aura: сначала требуется `Unequip`, затем `Equip` другой.
- Активная Aura переживает logout/restart и не затрагивается Mastery Reset.
- Коллекция фильтруется по rarity.
- Pinned Aura отображаются первыми.
- Active и pinned Aura нельзя использовать как расходники craft/dismantle.
- Dangling `activeAuraId` при загрузке автоматически очищается.

## Craft

Craft работает между соседними rarity:

`N x rarity[T] -> 1 x rarity[T+1]`.

Количество требуемых Aura задаётся Balance Core. Input effects, rolls и seeds не наследуются.

Craft result всегда является новой Aura instance:

- новый `instanceId`;
- новый seed;
- новые raw rolls;
- новый aggregate;
- `origin = CRAFT`.

`MYTHIC` нельзя craft дальше.

Auto Fill выбирает только подходящие Aura той же rarity, исключая active и pinned. Auto Fill только готовит selection. Выполнение craft требует отдельного подтверждения.

## Dismantle

Dismantle работает в обратную сторону:

`1 x rarity[T+1] -> configured count x rarity[T]`.

Количество возвращаемых Aura хранится отдельным параметром Balance Core и не вычисляется Java-кодом из craft cost.

Каждая возвращённая Aura получает новый id, новый seed, новые rolls/effects и `origin = DISMANTLE`.

`COMMON` dismantle запрещён. Active/pinned Aura нельзя dismantle. UI сначала показывает preview и только повторное действие подтверждает mutation.

## Persistence и Mastery independence

Aura state добавлен в существующий player document обратно-совместимым полем `auraState`; глобальный schema bump для старых v2.8.0 save не требуется.

Сохраняются:

- owned Aura collection;
- active Aura id;
- pin state;
- generation seeds;
- raw rolls;
- aggregated-effect audit data;
- chest counters;
- `Skip Animation` preference.

При отсутствии Aura state старый save загружается с нулевым количеством Aura и без active Aura.

Mastery Reset и существующие run reset hooks не очищают Aura collection, active Aura, pinning или Aura Keys.

## Gameplay events и future hooks

Добавлены factual events:

- `AURA_CHEST_OPENED`;
- `AURA_DROPPED_FROM_CHEST`;
- `AURA_CRAFTED`;
- `AURA_DISMANTLED`;
- `AURA_EQUIPPED`;
- `AURA_UNEQUIPPED`;
- `AURA_KEY_GAINED`.

Chest-drop event содержит instance metadata, rarity, origin и aggregate/raw-roll summary, чтобы будущие progression-системы могли считать фактические Aura drops.

Achievements System в `v2.9.0` не реализуется. Добавлены только совместимые factual hooks для будущей версии.

## Network и server authority

Aura использует отдельные network discriminators `21/22`.

Клиент может отправить только intent:

- sync;
- open;
- equip/unequip;
- pin/unpin;
- skip-animation preference;
- craft selection;
- dismantle selection.

Клиент не задаёт rarity результата, rolls, magnitude, seed, Crystal price или количество generated Aura. Для mutation используется monotonic nonce guard против повторного применения старого запроса; limiter очищается при shutdown.

## UI

Добавлен функциональный Aura screen, открываемый клавишей `U`.

Экран содержит:

- Aura Key и Crystal balance;
- цену недостающего ключа;
- Open x1/x3/x5/x10;
- `Skip Animation` preference;
- collection;
- rarity filter;
- pinned-first ordering;
- active/pinned markers;
- aggregated effects;
- сохранённые raw rolls;
- Equip / Unequip;
- Pin / Unpin;
- Auto Fill + craft preview/confirm;
- dismantle preview/confirm.

Это функциональный structured UI. Финальный визуальный polish, отдельный Aura NPC art и сложные chest animations не являются частью scope `v2.9.0`.

## Balance Core

Добавлен overlay `balance/v2.9.0-auras.json`.

Через Balance Core задаются:

- feature gate;
- Aura Key Crystal price;
- allowed chest quantities;
- rarity enabled/drop weight;
- min/max roll count;
- craft cost;
- dismantle return count;
- effect enabled/weight;
- effect min/max percent.

Текущие числовые значения имеют статус **ZBT Draft**. Release-stable является архитектура и data-driven contract, а не финальный production balance этих чисел.

## Проверки и регрессия

Добавлены тесты для:

- raw-roll duplicate aggregation;
- deterministic known-seed generation;
- missing-key purchase;
- insufficient-Crystal no-mutation path;
- equip/unequip rule;
- active/pinned consume protection;
- craft/dismantle origin and fresh generation;
- chest counter isolation;
- late ALL_DAMAGE + channel stacking;
- Balance overlay;
- backward-compatible Mongo persistence;
- dangling active-reference repair;
- Aura Key fixed resource catalog.

Полный существующий regression suite продолжает покрывать God Worship, Pets, Runes, Quests, Mastery/Reset, Run Exchange, resources, networking, architecture/security guards и packaged JAR contract.

## Вне scope v2.9.0

Не входят в релиз:

- Aura XP и Aura levels;
- Achievements System;
- Quest rewards в Aura Keys;
- финальный production balance Aura;
- финальный Aura art/NPC/chest animation;
- Mechanic Unlock System как отдельная система;
- новые post-3.0 механики.
