# RE:volution Mod v1.3.2

v1.3.2 переносит администрирование из встроенной Minecraft F8-панели во внешний приватный Windows-клиент и добавляет защищённый локальный Admin API. Игровая механика Realm/Location/Mob Position в эту версию не входит.

## Изменения

- Удалены F8 Admin/Test Panel, клиентский key handler и старый Forge packet transport панели. Дискриминаторы 5 и 6 остаются зарезервированы, `RuneEnhancementPacket` сохраняет ID 7.
- Серверная admin-бизнес-логика сохранена и разделена на типизированные `AdminOperationsService` и `AdminQueryService`; строковый generic action dispatcher не используется.
- Добавлен versioned Admin API `/api/v1`, доступный только через `127.0.0.1` на dedicated server. API не имеет прямого доступа к MongoDB и выполняет чтения/изменения Minecraft runtime через server-thread handoff.
- Добавлена отдельная аутентификация External Admin API: installation secret вне репозитория, HMAC-SHA-256 challenge-response, одноразовые challenge, короткоживущие memory-only session tokens, rate limiting и capability-based authorization.
- Добавлены строгие allowlisted routes для Status, Players, Resources, Runes/Enhancements и Managed Mobs. Mutation body ограничены по размеру и схеме, неизвестные/дублированные поля отклоняются до побочных эффектов.
- Для Managed Mobs добавлена типизированная операция установки spawn на текущую позицию выбранного игрока: координаты читаются с живого `EntityPlayerMP` непосредственно на Minecraft server thread.
- Installation secret защищён от linked-file substitution; при поддержке файловой системы создаётся с owner-only permissions. Secret, proof и session token не выводятся в логи/ошибки.
- Сессии сбрасываются при остановке/restart Admin API; CORS отключён, remote/wildcard bind запрещён контрактом v1.3.2.
- Добавлены security/architecture guards и regression tests для auth, challenge replay/expiry, session lifecycle, capabilities, input validation, loopback-only bind, server-thread handoff и wire discriminator contract.

## Внешняя админка

Приватный `REvolutionAdmin.exe` развивается в отдельном репозитории и не входит в публичный JAR. Клиент использует только типизированный Admin API и не подключается к MongoDB напрямую.

Runtime acceptance подтвердил Status/Players/Resources/Runes/Mobs, общий выбранный target-player, authoritative refresh до/после mutation, live spawn-at-player, форматы больших чисел, searchable unit selector, поиск managed mobs и тёмный интерфейс. Поиск мобов уже резервирует синтаксис `l2`, `m4`, `l2m4` для будущих Location/Mob индексов, но сами эти поля будут добавляться в последующих версиях.

## Совместимость

Minecraft 1.12.2, Forge 14.23.5.2859, Java 8, игровой network channel `revolution:main`, существующая Mongo schema и gameplay-механики сохранены. External Admin API независим от Forge packet channel.

Команды `/adminpanel`, `/custommob`, `/customresource`, `/customstatus` и `/customrunes` остаются серверными инструментами и продолжают использовать существующий UUID whitelist. Удаляется только встроенная F8 GUI/transport панели.

## Проверки

Feature runtime acceptance выполнен на Test server. Подтверждены loopback Admin API, HMAC/session auth, типизированные reads/mutations, live sync, актуальная позиция игрока при spawn моба, dark UI и отсутствие старой F8 панели. Финальный release-prep HEAD дополнительно должен пройти exact-head CI с version/release guards, Java regressions, architecture/security guards и сборкой JAR.

## Загрузка

После публикации используйте `RE-volution-1.3.2.jar` на сервере и клиентах с модом. Приватный `REvolutionAdmin.exe` публикуется отдельно в приватном admin-репозитории и не должен распространяться как часть публичного mod release.
