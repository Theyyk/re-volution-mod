# RE:volution Mod v1.4.7

## Назначение релиза

`v1.4.7` добавляет безопасный Admin/Control workflow для просмотра, проверки и атомарного применения полного Balance Core snapshot без обхода существующей валидации.

## Admin Balance Preview / Apply

Добавлены защищённые Admin API возможности `balance.read` и `balance.write` и маршруты:

- `GET /api/v1/balance` - текущая active revision, schema version и canonical JSON;
- `POST /api/v1/balance/preview` - подготовка полного candidate config без изменения runtime;
- `POST /api/v1/balance/apply` - применение только ранее подготовленного preview по opaque token.

Preview проходит тот же parser, semantic validator и deterministic revision codec, что и обычный Balance Core. Невалидный candidate не меняет active snapshot.

## Safety contract

- Preview привязан к текущей active revision.
- Preview привязан к authenticated Admin session и не может быть применён другой сессией.
- Preview живёт 120 секунд.
- Pending preview state ограничен и хранится только в памяти.
- Новый preview той же сессии заменяет предыдущий pending preview этой сессии.
- Apply одноразовый.
- Apply активирует именно immutable snapshot, подготовленный на Preview, а не повторно парсит новый request body.
- Активация использует atomic compare-and-set по expected active revision. Если balance изменился после Preview, apply отклоняется без частичной активации.
- После успешного apply остальные pending preview очищаются как устаревшие.

## Security boundary

Balance routes используют существующую loopback-only Admin API границу, HMAC challenge/session authentication, capability checks и Minecraft server-thread handoff. Секреты, токены и candidate config не записываются в mutation audit log.

## Что не меняется

`v1.4.7` не меняет реальные bundled balance values. Mob identity/type, population, модели, PNG, spawn coordinates, zones, stage/world topology и Mongo schema остаются вне Admin Balance Apply. Текущие Rune и Mob Balance runtime contracts сохраняются.

## Проверки

Добавлены regression tests для:

- Preview без мутации active snapshot;
- применения exact prepared snapshot;
- одноразового preview token;
- cross-session rejection;
- stale revision rejection;
- invalid candidate rejection без изменения active balance.

Полный Forge build, architecture guards и Admin API security guards остаются обязательными.
