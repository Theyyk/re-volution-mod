# RE:volution Mod v1.5.2

## Назначение релиза

`v1.5.2` расширяет ZBT enhancement policy и закрывает несколько runtime-проблем managed-мобов, подтверждённых на DEV.

Числа баланса по-прежнему имеют статус ZBT Draft, не Final. Остальные балансные значения не меняются.

## Безлимитные усиления рун

Hard cap усилений после `+50` удалён.

Контракт цены:

- для `totalEnhancements <= 50` используется существующая таблица без изменений;
- последняя явно заданная стоимость таблицы остаётся `12440` Пыли на `+50`;
- после последней явной точки TABLE curve продолжается data-driven tail с `tail_growth = 1.10`;
- цена следующего усиления выводится из фактической суммы enhancement levels всех 26 слотов, а не из исторического счётчика.

Контрольные точки хвоста:

- `+51 = 13684`;
- `+60 = 32266`;
- `+75 = 134784`;
- `+100 = 1460342`;
- `+150 = 171430818`.

RNG выбора слота не меняется: участвуют все 26 слотов, включая пустые. Enhancement остаётся свойством слота и сохраняется через rank-up/revert. Формула силы не меняется: `enhancementMultiplier = 1 + 0.10 * slotEnhancementLevel`.

Цена и Dust transport переведены на `BigDecimal`, чтобы хвост корректно работал существенно выше `+100/+150` без integer overflow и отрицательных значений.

GUI после `+50` показывает цену следующего усиления или обычное состояние нехватки Пыли. Состояние `Превышает лимит` больше не является runtime policy.

## Managed mob display hotfix

Убран краткий визуальный fallback на vanilla zombie при получении урона и последующий микроскачок технического имени `Mob1_1`.

HP sync теперь сохраняет visual identity и player-facing display name в одном wire payload, поэтому технический mob ID остаётся внутренним идентификатором и не должен кратко появляться над мобом.

## Pre-1.9 melee cadence для managed-мобов

Для direct melee по RE:volution managed-мобам убрано ванильное 1.12.2 снижение урона от attack cooldown.

Дополнительно bypass-ится `hurtResistantTime` для точно сопоставленного direct player melee удара, чтобы быстрые одинаковые клики не отбрасывались до `LivingHurtEvent`.

Ограничения фикса:

- действует только на managed-мобов;
- не меняет глобальный `ATTACK_SPEED`;
- не включает искусственно sweeping/прочие fully-charged эффекты;
- projectile, poison и secondary damage не используют этот bypass;
- существующая RuneCombatMath продолжает применяться поверх полного primary click damage.

Поведение подтверждено на DEV с быстрым ручным кликом и кликером: каждый клик проходит без прежнего среза/пропусков.

## Что не меняется

- Purchase base curve и pressure `1.15 ^ higherRuneCount` не меняются.
- Duplicate compensation и rank-up curve не меняются.
- Rune Rank Revert остаётся data-driven и сохраняет enhancement.
- Poison/AoE balance не меняется.
- Location 1 HP/reward values не меняются.
- Rank 4 не добавляется.
- Mongo schema не меняется.
- Balance Core schema version остаётся прежней.
