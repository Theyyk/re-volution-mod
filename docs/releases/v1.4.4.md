# RE:volution Mod v1.4.4

`v1.4.4` переводит Rune Rank Up / Awakening на canonical Balance Layer и исправляет прогрессию покупки после пробуждения: активный этап теперь выводится из фактических рангов рун, а не из исторического счётчика или жёсткого `NORMAL_RANK`.

## Добавлено

- `RuneRankUpRule` — неизменяемое описание одного перехода ранга.
- `RuneRankUpBalanceService` — rune-domain адаптер для target rank, required slots, ресурса, стоимости, clear mode и правила сохранения усилений.
- `RuneCollectionProgression` — чистая производная модель текущего purchase-stage из фактических рангов 26 рун.
- Canonical rank-up ключи для Poison переходов `NORMAL → IMPROVED` и `IMPROVED → ADVANCED`.
- Purchase/duplicate curves для рангов 2 и 3.
- JUnit-покрытие data-driven переходов, derived progression, локального изменения ранга и текущего bundled baseline.

## Исправлено

- Status-покупка больше не создаёт новые руны всегда как `NORMAL` после пробуждения.
- Стоимость следующей покупки больше не опирается на отдельный исторический purchase index: индекс выводится из текущего состояния коллекции.
- Rank-up payment больше не читает legacy economy properties напрямую и получает уже разрешённое правило из Balance Core.
- Required slots и target rank больше не зашиты в runtime awakening path.

## Текущий baseline

Для Poison намеренно сохранены placeholder-значения:

- покупка каждого поддерживаемого ранга — `100 coins`;
- duplicate reward — `1 rune_dust`;
- `NORMAL → IMPROVED` — требуется 26 подходящих рун, стоимость `100 rune_dust`;
- `IMPROVED → ADVANCED` — требуется 26 подходящих рун, стоимость `100 rune_dust`;
- clear mode — `AT_OR_BELOW_SOURCE`;
- enhancement levels сохраняются.

## Архитектура прогрессии

Источник истины — фактические ранги конкретных рун. Отдельный `currentCollectionRank`, сохранённый `nextPurchaseCost` или исторический purchase index не вводятся.

Текущий расчёт следует схеме:

`Collection State → Progression Index → Purchase Curve → Next Purchase Cost`.

Это важно для будущей механики локального отката одной руны: изменение ранга одной руны автоматически меняет derived progression при следующем расчёте. Сам player-controlled rank revert в `v1.4.4` не реализуется и запланирован отдельно на `v1.4.9`.

## Совместимость

- Новая Mongo/player schema migration не требуется.
- Existing rune records остаются источником фактических рангов.
- Enhancement persistence не меняется.
- Network wire format не меняется.
- Rune Effects остаются следующим этапом `v1.4.5`.

## Проверки

Release candidate должен пройти полный Gradle build, JUnit/standalone regression tests, architecture/security guards, packaged-resource verification и version/README consistency validation. Stable tag создаётся только после успешного exact-main CI.
