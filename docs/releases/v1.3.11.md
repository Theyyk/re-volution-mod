# RE:volution Mod v1.3.11

`v1.3.11` расширяет персональную progression с отдельных mob-stage до последовательности Location и вводит явную Boss Zone как финальную стадию Location.

## Что добавлено

### Progression между Location

- Progression остаётся персональной для игрока и серверно-авторитетной.
- Внутри Location стадии идут по настроенным `mobSlotId`.
- После победы в финальной Boss Zone открывается первый настроенный stage следующей Location.
- Следующая Location может существовать даже без population: сама `LocationDefinition` определяет существование stage, а `populate` определяет только содержимое зоны.
- Если следующая Location ещё не создана, progression корректно останавливается на текущем доступном контенте без автогенерации и без ошибки.
- `/stage next` и `/stage previous` умеют переходить через границу Location при наличии доступа и transition point.
- `/stage teleport <locationId> <mobSlotId> [player]` остаётся каноническим административным teleport API и не открывает progression.

### Boss Zone foundation

- Обычная mob-zone и Boss Zone теперь различаются в доменной модели.
- Типы зон: `MOB_ZONE` и `BOSS_ZONE`.
- Для корректно завершаемой Location разрешена ровно одна Boss Zone, и она должна быть финальным configured stage.
- Последний обычный mobSlot больше не считается боссом автоматически.
- Невалидная конфигурация с несколькими Boss Zone или Boss Zone не в конце не может открыть следующую Location.
- Существующие legacy-зоны без явного типа читаются как обычные `MOB_ZONE`, разрушительная миграция данных не требуется.
- Команды настройки:

```text
/stage location setboss <locationId> <mobSlotId>
/stage location clearboss <locationId> <mobSlotId>
```

- `/stage location list [locationId]` отображает тип стадии.

Boss Zone является фундаментом для будущих механик босса, но динамический HP scaling, boss ability reward, индивидуальные kill limits и отдельные respawn policies в `v1.3.11` не входят.

### Fast-auto

- Добавлен отдельный персональный persistent `fastAutoEnabled`, независимый от существующей trigger-zone automation.
- Переключатель находится в меню переходов по клавише `L`.
- При `Fast-auto: ON` после успешного unlock следующей стадии сервер пытается переместить игрока к её transition point.
- Обычная стадия ведёт на следующий mobSlot текущей Location.
- Победа в Boss Zone ведёт на первый configured stage следующей Location.
- Сервер повторно проверяет progression и destination перед фактическим перемещением, поэтому fast-auto не обходит access rules.

### Динамическая Boss-подпись в меню L

- Меню получает актуальный `boss` flag из серверного snapshot.
- Обычная стадия отображается как `Моб N`.
- Boss Zone отображается как `Босс`.
- После снятия boss-статуса и повторного открытия меню подпись снова становится `Моб N`.
- Состояние не захардкожено на клиенте и формируется из текущего server-side `LocationDefinition`.

## Исправлено

- Исправлена topology progression для пустой, но уже созданной следующей stage: `LocationDefinition` теперь является источником истины для существования stage, а отсутствие population не скрывает stage от progression.
- Устранена возможность случайно завершить Location через последний обычный mobSlot без явной Boss Zone.
- Добавлена regression-защита server-authoritative GUI/network flow для fast-auto и Boss state.

## Проверки

Автоматические проверки покрывают, среди прочего:

- normal zone vs Boss Zone;
- корректность единственной финальной Boss Zone;
- boss -> next Location unlock;
- отсутствие next Location;
- пустой configured stage следующей Location;
- fast-auto ON/OFF и boss -> next Location;
- revoke/reset и закрытые будущие Location;
- server-side validation клиентских запросов;
- wire contract меню переходов и boss flag;
- динамический label `NORMAL -> Моб N`, `BOSS -> Босс`, затем обратно `NORMAL -> Моб N`.

На финальном DEV baseline перед release preparation выполнялось 45 JUnit tests без ошибок и без skipped tests, плюс существующий набор standalone regression/architecture checks.

## Runtime acceptance в DEV

В реальном Minecraft DEV подтверждены:

- переключение Fast-auto через `L`;
- fast-auto между обычными mob stages;
- Boss Zone назначается и сохраняется;
- победа в Boss Zone открывает stage следующей Location;
- динамическая подпись `Босс` отображается в `L` и возвращается к обычной после снятия boss-статуса.

## Не входит в v1.3.11

Отложено на будущие версии:

- автоматическая генерация новых Location;
- процедурная сборка Location по строительным шаблонам;
- HP босса в зависимости от количества игроков в Boss Zone;
- выдача способности босса после победы;
- индивидуальные ограничения на убийство босса;
- boss-specific enter/leave hooks и отдельные respawn/reset policies.
