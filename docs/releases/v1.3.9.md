# RE:volution Mod v1.3.9

`v1.3.9` добавляет переходы между mob stages внутри одной Location поверх персональной progression из `v1.3.8`.

## Основная модель

Progression по-прежнему принадлежит `mobSlot`, а переходы являются отдельной player/Location-механикой.

- Переход не открывает stage и не может перескочить progression.
- Соседние stage выбираются по настроенному порядку существующих стадий, поэтому ID могут быть с пропусками.
- `autoTransitionEnabled` является единым флагом игрока и сохраняется между relog/restart.
- Переходы между разными Location, boss unlock и scaling в этот контракт не входят.

## Transition points

Для каждого stage можно настроить явную destination point:

```text
/stage setpoint <locationId> <mobSlotId>
/stage setpoint <locationId> <mobSlotId> <x> <y> <z> [yaw pitch]
/stage clearpoint <locationId> <mobSlotId>
```

Точка может находиться в любом месте мира. Перед перемещением сервер проверяет свободный bounding box игрока и твёрдую опору под destination. Небезопасная точка отклоняется без скрытого поиска случайного места рядом.

## Trigger-зоны

Trigger-зона настраивается сразу для всей Location:

```text
/stage settrigger <locationId> <offset> <radius>
/stage cleartrigger <locationId>
```

Для mob-zone радиуса `R`:

- `innerRadius = R + offset`;
- `outerRadius = R + offset + radius`.

Все mob stages одной Location получают одинаковые `offset/radius`; разные Location могут использовать разные размеры.

Кольцо автоматически делится на две половины по 180°:

- forward ведёт к следующему уже открытому stage;
- backward ведёт к предыдущему уже открытому stage.

Ориентация строится из геометрии соседних stage, а не из направления камеры администратора.

## Сообщения и задержка

Тексты задаются сразу для всей Location:

```text
/stage setmessage <locked|forward|backward> <locationId> <text...>
/stage clearmessage <locked|forward|backward> <locationId>
```

Tab completion после `setmessage` и `clearmessage` предлагает `locked`, `forward`, `backward`.

При входе в доступную trigger-зону сообщение показывается сразу, затем начинается задержка 20 ticks (примерно 1 секунда). Телепорт выполняется только если игрок всё ещё находится внутри нужной половины зоны и progression по-прежнему разрешает переход. Выход из зоны, отключение auto, удаление trigger или потеря контекста отменяют pending transition.

Locked-направление показывает сообщение сразу и не запускает таймер.

## Ручные переходы и teleport

```text
/stage next [player]
/stage previous [player]
/stage teleport <locationId> <mobSlotId> [player]
/stage auto <on|off> [player]
```

`next/previous` используют текущую/запомненную Location context и перемещают только на соседний уже открытый stage.

`teleport` использует transition point выбранного stage и не изменяет progression. Сервер повторно проверяет stage, unlock и безопасность destination перед перемещением.

## Меню быстрого перехода

Клавиша `L` открывает player navigation menu:

1. выбор Location;
2. выбор mob/stage внутри Location;
3. teleport в transition point выбранного уже открытого stage.

Locked stage отображается как недоступный. Открытый stage без transition point также нельзя выбрать для телепорта. Клиент отправляет только запрос; authoritative validation остаётся на сервере.

## Progression revoke/reset

```text
/stage revoke <locationId> <mobSlotId> [player]
/stage reset <locationId> [player]
```

`revoke` закрывает указанный stage и все последующие stage этой Location, а также очищает progression более поздних Location. `reset` сбрасывает указанную Location и все последующие. Первый настроенный stage Location после reset остаётся базово доступным согласно progression contract.

## Location-команды

Канонический namespace для mob-zone configuration перенесён в `/stage location`:

```text
/stage location set <locationId> <mobSlotId> <radius>
/stage location populate <locationId> <mobSlotId> <mobName> <count>
/stage location clear <locationId> <mobSlotId>
/stage location remove <locationId> <mobSlotId>
/stage location here
/stage location list [locationId]
```

Старый `/custommob location ...` сохранён как legacy alias для обратной совместимости.

## Overlay

Существующий клиентский mob-zone overlay расширен transition geometry:

- mob-zone остаётся базовой зоной;
- для настроенного trigger отображаются внутренняя и внешняя границы кольца;
- forward/backward половины соответствуют той же серверной геометрии, которая используется runtime-переходами;
- если направление определить нельзя, trigger отображается нейтрально;
- если trigger не настроен, дополнительная trigger geometry не отображается.

## Runtime acceptance

Перед stable release фактически проверены:

1. explicit transition points и безопасный teleport;
2. `next/previous` между уже открытыми стадиями;
3. trigger offset/radius и разделение forward/backward по 180°;
4. location-wide trigger configuration;
5. location-wide `locked/forward/backward` messages и Tab completion;
6. задержка 20 ticks и отмена pending transition при выходе из зоны;
7. locked gate без progression bypass;
8. `revoke/reset` cascading semantics;
9. transition overlay без регрессий основной mob-zone визуализации;
10. `/stage teleport` и меню `L` с серверной progression/safety validation;
11. `/stage location ...` как канонический namespace при сохранённом legacy alias.

Следующая техническая итерация после закрытия `v1.3.9` планируется как `v1.3.10 Test Foundation`: JUnit, `src/test/java` и выделение критичной логики из Forge/Minecraft API там, где это необходимо для unit/regression tests.
