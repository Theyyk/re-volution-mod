# RE:volution Mod v1.4.9

## Назначение релиза

`v1.4.9` добавляет локальный одноступенчатый Rune Rank Revert для одной выбранной руны и завершает текущий контракт progression, где фактические ранги коллекции остаются единственным источником истины для следующей покупки и её цены.

## Rune Rank Revert

Игрок может откатить одну выбранную руну ровно на один ранг вниз, начиная с ранга `Продвинутая`.

Текущий runtime поддерживает ранги:

- `Обычная`;
- `Улучшенная`;
- `Продвинутая`.

Поэтому фактический доступный откат в `v1.4.9` - `Продвинутая -> Улучшенная`. Контракт сформулирован одноступенчато и не требует отдельного persisted состояния для будущих более высоких rank IDs.

Откат `Улучшенная -> Обычная` игроку запрещён.

## Что сохраняется

При откате выбранной руны:

- меняется только её rank;
- остальные руны коллекции не изменяются;
- enhancement level выбранной руны сохраняется;
- enhancement levels остальных рун не изменяются;
- коллекция целиком не очищается и не восстанавливается из исторического snapshot.

Persistence использует существующий selected-rune `setRuneRank`, поэтому Rank Revert не вводит отдельную schema или историю коллекции.

## Экономика

Сам Rank Revert бесплатный.

Он:

- не списывает ресурс;
- не возвращает ранее потраченный ресурс;
- не выдаёт refund или дополнительную награду.

Если игрок после отката снова повышает ранг через обычную механику rank-up, применяется полная текущая стоимость rank-up.

## Purchase progression после отката

Источник истины - фактические per-rune ranks.

После отката:

- `RuneCollectionProgression` заново выводит active purchase stage;
- progression index заново считается как количество рун фактического active rank;
- следующая data-driven purchase price берётся из нового фактического `stageRank + progressionIndex`;
- duplicate reward также продолжает использовать фактическую progression point.

Отдельного persisted `purchaseIndex`, `currentCollectionRank` или `nextPurchaseCost` для этой механики нет. Никакой операции вида `purchaseIndex--` не выполняется.

Для полной коллекции из 26 `Продвинутых` рун откат одной выбранной руны даёт фактическое состояние `rank 3 / progression index 25`, потому что остальные 25 рун остаются `Продвинутыми`.

## Клиентский ввод

В текущем GUI:

- левый клик сохраняет существующее действие пробуждения/rank-up;
- правый клик по подходящей руне отправляет Rank Revert;
- search-hidden руна не является target;
- руна ниже допустимого ранга не является target.

Сервер остаётся authoritative и повторно валидирует status, rune index и фактический rank перед записью.

## Синхронизация следующей цены

`PlayerStatsSyncService` теперь получает тот же активный `RunePurchaseBalanceService`, который использует серверная покупка. Поэтому после Rank Revert клиент получает фактическую следующую data-driven цену, вычисленную из текущих рангов коллекции, а не старый статический fallback.

Legacy/fallback path сохраняется для контекстов, где Balance adapter не привязан.

## Проверки

Добавлены regression tests для:

- `Продвинутая -> Улучшенная` ровно на один шаг;
- запрета `Улучшенная -> Обычная`;
- missing и invalid rune states;
- неизменности остальных рангов;
- factual progression `26 -> 25` после отката одной руны полной продвинутой коллекции;
- повторного restore/revert без hidden progression drift;
- пересчёта data-driven purchase price из фактического progression index;
- right-click selection, GUI scaling, search filtering и rank eligibility.

Полный Forge build, architecture guards и существующие security/regression checks остаются обязательными.

## Что не меняется

- Mongo schema не меняется.
- Rune enhancement persistence не меняется.
- Balance Core schema не меняется.
- Rank-up экономика остаётся data-driven и оплачивается обычным способом.
- Mob Balance, Admin Balance Preview/Apply и Balance Export Contract не меняются.
- Новые rank IDs выше `Продвинутая` в `v1.4.9` не добавляются.
