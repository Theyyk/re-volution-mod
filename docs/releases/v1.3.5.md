# RE:volution Mod v1.3.5

`v1.3.5` вводит foundation для Location и Mob Spawn поверх готовой Realm-модели `v1.3.4`.

## Location model

- `Location ID` является отдельным gameplay-идентификатором и не равен Realm ID, Dimension ID, Mob ID или UUID сущности.
- Каждая Location имеет круглую рабочую зону по X/Z: `centerX`, `centerZ`, `radius`.
- Эта же зона используется как область случайного спавна для `RANDOM_AREA` и как допустимая зона перемещения для `ROAMING`.
- Y для случайного спавна намеренно не хранится в зоне: runtime должен определить поверхность мира позже.

## Mob Spawn model

- Один `MobSpawnDefinition` представляет ровно один физический слот моба.
- Если требуется 10 одинаковых мобов, создаются 10 Mob Spawn с разными Spawn ID, но одним `mobId`.
- Статы и тип моба не копируются в spawn-slot: несколько слотов переиспользуют одну Mob Definition.
- У каждого Mob Spawn сохраняется собственная фиксированная стартовая точка X/Y/Z и ориентация.
- Фиксированная точка остаётся fallback/reset-точкой даже при `RANDOM_AREA`.

## Переключаемые режимы

Spawn и movement настраиваются независимо:

- `FIXED_POINT` + `STATIONARY` — фиксированная точка, моб стоит на месте.
- `FIXED_POINT` + `ROAMING` — фиксированная точка появления, затем движение по Location Area.
- `RANDOM_AREA` + `STATIONARY` — случайная точка внутри Location Area, после появления моб стоит.
- `RANDOM_AREA` + `ROAMING` — случайная точка внутри Location Area и движение по той же зоне.

Такой контракт позволяет в следующих версиях переключать поведение для тестирования комфорта игроков без изменения Mob Definition.

## Realm scope

- Realm 1, Realm 2 и Realm 3 используют одни и те же Location/Mob Spawn определения и координаты; различается только Forge dimension.
- Realm 0 не получает player-Realm спавны автоматически.
- Для Realm 0 существуют только Mob Spawn, которые явно созданы со scope `REALM_0`.

## Runtime, отложенный на следующий этап

В foundation `v1.3.5` намеренно не входят:

- фактический entity spawn;
- respawn loop;
- поиск surface Y;
- roaming AI и выбор маршрута;
- ранний разворот перед границей Location;
- аварийный возврат на стартовую точку после выхода за границу;
- rewards, progression и scaling.

Эти механики должны потреблять стабильный Location/Mob Spawn контракт, а не смешиваться с его моделью данных.
