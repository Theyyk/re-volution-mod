# RE:volution Mod v1.4.0

`v1.4.0` завершает цикл инструментов управления и административного QoL, проверенный на DEV перед стабильным promotion.

Добавлены серверные API общего Control/Admin: просмотр progression, выдача доступа к stage, сброс текущей и последующих стадий, отдельной локации или всей progression. Новый редактор стадий поддерживает HP, population и ресурс/размер награды, предварительный diff и применение только выбранных полей.

Список игроков включает сохранённые offline-профили. Для offline-профилей ресурсы можно устанавливать, добавлять и обнулять напрямую по UUID через Mongo; live-only действия, включая руны, усиления и progression, остаются недоступны до входа игрока. Последнее известное имя сохраняется как `lastKnownName`.

Выдача stage открывает всю настроенную цепочку этой Location до выбранной стадии включительно. Добавлена отдельная DEV-операция выдачи заданного количества случайных постоянных усилений рун без списания ресурсов; запрос ограничен 100000 усилений и выполняется только для подключённого игрока.

Batch проходит Validate → Preview → Apply. Подготовка привязана к сессии, сроку действия и ревизии; журнал Mongo с подтверждением записи восстанавливает before-image незавершённого batch перед запуском runtime. Это не multi-document транзакция и не защита от независимых внешних writers.

При изменении population через Admin/Control enabled spawn slots нормализуются примерно 50/50: `FIXED_POINT = floor(population / 2)`, `RANDOM_AREA = ceil(population / 2)`, поэтому нечётный остаток всегда уходит в `RANDOM_AREA`. Disabled spawn-записи сохраняются.

API сообщает среду, публичный installation UUID и capabilities. Последняя configured stage остаётся автоматическим runtime/persisted boss; обычного ручного dropdown BOSS_ZONE нет.

Реальный баланс Location 1, boss mechanics, визуальный polish и template builder в этот релиз не входят. Совместный Control использует общий API-клиент; отдельный Admin сохраняется для ещё не перенесённых операций.

Проверены полные Gradle check/build, security/architecture guards, unit regression, standalone Mongo integration commit/stale/recovery и DEV runtime smoke для offline resource editing, live-only restrictions, progression actions и population redistribution. Подробный внутренний контракт: ../admin-1.4.0-preview.md.
