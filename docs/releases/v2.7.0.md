# RE:volution v2.7.0

## Основное

- Добавлена постоянная Generic Quest System с доской из 3 одновременных заданий.
- Все ACTIVE-задания получают factual progress параллельно; каждое задание содержит ровно одну objective.
- Награда за Quest в v2.7.0 - только Crystals.
- Завершённое задание не выдаёт награду автоматически: игрок вручную нажимает Claim.

## Lifecycle и cooldown

- Состояния Quest: `ACTIVE`, `COMPLETED`, `COOLDOWN`.
- Достигшая target задача становится `COMPLETED` и остаётся такой без срока истечения до ручного Claim.
- Успешный Claim атомарно выдаёт Crystals, увеличивает постоянный `completedQuestCount` и переводит entry в `COOLDOWN`.
- Первый Claim в новой группе запускает общий 8-часовой cooldown batch.
- Последующие Claim во время активного batch присоединяются к тому же deadline и не продлевают его.
- После истечения deadline заменяются только `COOLDOWN` entries; `ACTIVE` и `COMPLETED` сохраняются.
- Cooldown хранится абсолютным timestamp и корректно переживает logout/restart/offline время.

## Reroll и сложность

- Доступно до 2 успешных reroll за server-defined calendar day.
- Reroll заменяет только `ACTIVE` entries, не затрагивает `COMPLETED`, `COOLDOWN` и общий cooldown deadline.
- Если ACTIVE-заданий нет, попытка reroll не расходуется.
- `completedQuestCount` постоянный и увеличивается только после успешного Claim, а не при одном факте completion.
- Difficulty tier выводится из data-driven thresholds Balance Core.
- При генерации Quest target, filters, reward и difficulty snapshot фиксируются в entry и не изменяются задним числом при росте progression.
- Генератор использует weighted eligible pool и не допускает одинаковые objective variants на одной доске, включая будущие filtered variants.

## Server authority и factual events

- Клиент не сообщает kill count, damage, purchase count, Quest progress, completion или reward.
- Progress строится через общий factual `GameplayEvent` layer и server-side Quest router.
- В v2.7.0 подключены factual producers для кликов/ресурсов, managed mob rewards, Rune purchase/enhance/awaken, Pet purchase/level/awaken, Run Exchange, stage progression и Mastery progress/reset/fragment collection.
- Quest lifecycle не зависит от Mastery reset или смены ветки; при этом factual Mastery actions могут продвигать подходящие Quest objectives.
- Generic event contract заранее содержит точки расширения для будущих систем, включая God Worship, но сама God Worship mechanic в v2.7.0 не реализуется.
- `boss_kill` template оставлен disabled, пока нет отдельного гарантированного authoritative producer для финального boss fact; невозможные Quest не генерируются.

## Persistence и UI

- Quest state хранится отдельно от Mastery run state и обратно совместим с существующими save-документами.
- Для существующего игрока без Quest state создаётся начальная доска из 3 ACTIVE-заданий на стартовой сложности.
- Функциональный Quest UI открывается клавишей `Q` и показывает objective, progress/target, Crystal reward, state, Claim, общий cooldown и остаток reroll.
- UI использует server-authoritative snapshots и остаётся функциональным skeleton без финального Tavern/city visual polish.
- Quest network использует новые discriminators `17` и `18`, не меняя существующие packet IDs и зарезервированные `5/6`.

## Balance Core

- Добавлен bundled overlay `balance/v2.7.0-quests.json`.
- Cooldown, reroll limit, difficulty thresholds, template enable flags, weights, targets и Crystal rewards data-driven.
- Текущие числовые Quest параметры имеют статус ZBT Draft и предназначены для функционального тестирования/дальнейшего баланса без переделки core architecture.

## Проверки

- Regression coverage проверяет начальную доску, parallel factual progress, completion, manual one-shot Claim, shared cooldown batch, selective cooldown refresh, ACTIVE-only reroll, disabled templates и Quest packet round trips.
- Release CI проверяет Java 8 build/tests, architecture/resource contracts, version consistency и содержимое итогового JAR.
