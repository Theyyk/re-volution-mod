# RE:volution Mod v1.4.6

## Назначение релиза

`v1.4.6` добавляет runtime-слой **Mob Balance** поверх существующего Balance Core. Балансовые параметры канонических stage-мобов теперь могут читаться из активного balance snapshot без изменения технической идентичности моба, world topology или Mongo schema.

## Mob Balance

Для канонического технического имени `Mob<locationId>_<mobSlotId>` поддерживаются необязательные ключи:

- `mobs.location.<locationId>.slot.<mobSlotId>.hp`;
- `mobs.location.<locationId>.slot.<mobSlotId>.resource`;
- `mobs.location.<locationId>.slot.<mobSlotId>.reward`.

Каждое поле разрешается независимо. Если override отсутствует, используется текущее значение из persistence. Поэтому существующие настроенные mob definitions остаются обратносуместимым fallback и bundled-конфигурация `v1.4.6` не меняет текущие игровые HP/награды сама по себе.

## Runtime contract

- Balance overrides применяются только к каноническим `MobL_N`.
- Legacy/non-canonical mob names остаются полностью persistence-driven.
- HP и reward amount должны быть положительными значениями.
- Reward resource обязан быть известным canonical resource id.
- Mongo writes и Mongo schema не изменены.
- Mob type, display identity, модели, PNG, spawn coordinates, population, movement mode, зоны, stage geometry и world topology не являются частью Mob Balance.
- Runtime использует тот же активный `BalanceService` snapshot, что и rune systems.
- Изменение balance не переписывает уже существующую физическую жизнь моба в середине жизни; новое разрешённое значение используется при следующей загрузке/respawn workflow, который перечитывает определения.

## Совместимость

Bundled `default-balance.json` в этом релизе не содержит выдуманных mob HP/reward значений. Реальные настроенные значения продолжают приходить из текущего persistence, пока соответствующий canonical override явно не опубликован в Balance Core.

Это сохраняет gameplay baseline и не переносит неизвестные production-значения в исходный код.

## Проверки

Добавлен `MobBalanceServiceTest`, который покрывает:

- отсутствие изменения текущих persistence values при bundled defaults;
- HP/resource/reward override для canonical mob;
- независимые partial overrides с fallback для пропущенных полей;
- совместимость non-canonical mobs;
- legacy integer reward bridge;
- отказ на non-positive HP/reward и неизвестном resource id.

Architecture guard дополнительно подтвердил, что repository package остаётся ports-only: balance-aware decorator расположен в service layer, а persistence adapter остаётся отдельным Mongo implementation.

## Не входит в v1.4.6

- Admin Balance Preview/Apply - следующий этап `v1.4.7`.
- Перенос population в balance data.
- Изменение распределения `FIXED_POINT` / `RANDOM_AREA`.
- Изменение mob visuals, моделей или текстур.
- Изменение stage/boss topology.
- Подбор новых реальных HP/reward значений.
