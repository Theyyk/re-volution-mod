# RE:volution Mod v1.3.7

`v1.3.7` добавляет damage contribution для managed mobs, пропорциональные награды и HP rollback для конкретного физического runtime instance.

## Damage contribution

Для каждого физического managed-моба в mob-zone ведётся отдельная runtime-таблица вклада игроков.

- Вклад принадлежит конкретному spawn/runtime instance и не сохраняется в Mongo.
- Один и тот же логический mob в разных Realm, spawn-slot или после нового respawn имеет независимый contribution state.
- Учитывается только фактически снятый HP. Overkill ограничивается оставшимся HP моба и не увеличивает contribution/reward сверх реального урона.
- Для mob-zone урон засчитывается только пока игрок находится в той же dimension и внутри круга этой зоны.
- Legacy Realm 0 mob без Location/Mob Spawn продолжает использовать прежнюю last-hit reward семантику.

## HP rollback при выходе из зоны

Пока managed mob жив, runtime проверяет всех игроков с ненулевым contribution.

Если игрок больше не находится внутри mob-zone, его вклад удаляется, а мобу возвращается ровно нанесённый этим игроком урон:

`currentHp = min(maxHp, currentHp + playerContribution)`

Пример:

- max HP = 100;
- игрок A нанёс 40;
- игрок B нанёс 20;
- current HP = 40;
- A выходит из зоны;
- вклад A становится 0, мобу возвращается 40 HP;
- current HP становится 80, остаётся вклад B = 20.

После возвращения A начинает contribution заново с нуля.

Runtime eligibility требует, чтобы игрок оставался онлайн, в той же dimension и внутри круга mob-zone. При потере этой eligibility вклад откатывается тем же механизмом.

## Награды

После смерти managed-моба награду получают все актуальные участники, оставшиеся в его contribution table.

Базовая награда делится пропорционально фактическому damage:

- 51% damage -> 51% базовой награды;
- 49% damage -> 49% базовой награды.

После вычисления базовой доли к доле каждого игрока отдельно применяется его действующий reward bonus от рун. Расчёты используют `BigDecimal`, поэтому большие HP/reward значения не переводятся в `long`/`double` баланс.

Игрок, который вышел из зоны до убийства и получил HP rollback, не сохраняет reward claim.

## Max contributor

Runtime определяет одного лидера contribution для последующей progression-логики:

- выигрывает игрок с максимальным актуальным contribution;
- при точной ничьей выигрывает тот, кто раньше достиг текущего итогового значения вклада;
- last hit сам по себе не даёт приоритет.

В `v1.3.7` результат определяется и логируется на смерти managed-моба. Mongo progression/gating остаётся отдельным следующим этапом.

## Respawn и unload

Новый physical life всегда начинается с чистого состояния:

- contribution table очищается;
- HP возвращается к 100%;
- combat pause очищается.

Полная выгрузка spawn chunk также сбрасывает текущую попытку. При следующей загрузке/respawn моб стартует с полным HP и без старых contribution claims.

## Совместимость

- `FIXED_POINT` и `RANDOM_AREA` сохраняют существующую respawn-семантику.
- `ROAMING`, separation, combat pause, safe-surface и boundary behavior из `v1.3.6` не меняются.
- Vanilla drops/XP для managed mobs по-прежнему подавляются.
- Poison damage игрока участвует в contribution как player damage, но по-прежнему не запускает direct-hit roaming pause.

## Runtime acceptance

Перед release нужно проверить минимум два игрока в одной mob-zone:

1. A и B наносят разный damage одному мобу.
2. Проверить пропорциональные rewards после убийства.
3. Проверить 50/50 tie и отсутствие зависимости от last hit.
4. A наносит damage и выходит из зоны: его вклад исчезает, HP моба восстанавливается ровно на его damage.
5. A возвращается: его новый вклад начинается с нуля.
6. Уход одного игрока не удаляет contribution другого.
7. После смерти/respawn contribution полностью очищен.
8. После unload/load моб возвращается с полным HP и пустым contribution state.
9. Overkill не увеличивает contribution/reward сверх оставшегося HP.
10. Проверить, что roaming, respawn, poison, drops/XP и Realm isolation не получили регрессий.
