# v1.3.5 Location and Mob Spawn foundation

This foundation separates a mob definition from the physical spawn slots that instantiate it.

## Contract

- One `MobSpawnDefinition` represents one physical mob slot.
- Multiple spawn slots may reference the same `mobId`, so one mob type and one stat definition can be reused at many spawn points.
- `SpawnMode` and `MovementMode` are independent switches:
  - `FIXED_POINT` + `STATIONARY`
  - `FIXED_POINT` + `ROAMING`
  - `RANDOM_AREA` + `STATIONARY`
  - `RANDOM_AREA` + `ROAMING`
- A `LocationDefinition` owns one circular X/Z area defined by center and radius.
- `RANDOM_AREA` chooses X/Z inside that circle. Runtime surface-Y lookup is intentionally deferred.
- `ROAMING` uses the same Location circle as its movement boundary. Runtime AI/turnaround behavior is intentionally deferred.
- The configured spawn point remains present for `RANDOM_AREA` as a safe configuration fallback if runtime random surface resolution cannot find a valid point. Later runtime work may use the actually rolled random point as the current physical mob life's movement-recovery point.
- Player Realms 1, 2 and 3 share the same spawn definitions and coordinates; only the Forge dimension differs.
- Realm 0 receives only spawns explicitly scoped to `REALM_0`.

## Deferred runtime behavior

This version does not add entity spawning, respawn loops, roaming AI, surface-Y resolution, boundary steering, out-of-bounds teleport, rewards, progression or scaling. Those systems consume this contract in later runtime work.
