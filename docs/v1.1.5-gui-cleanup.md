# Архив: разделение GUI-кода v1.1.5

Исходная база: v1.1.4 / `develop` на коммите `0ce0a599147b73e8dc963222e266acb1bccc1955`. Этот документ сохраняет сведения о конкретном этапе рефакторинга; актуальная структура описана в [архитектуре](architecture.md).

## Область изменений

- `GuiControls` объединяет `PanelButton`, `ElementButton`, `NavButton`, прежние константы их оформления и идентификаторы действий.
- `GuiDrawing` содержит общий код отрисовки поверхностей с привязкой к пиксельной сетке и переиспользуемым буфером преобразования.
- `FlyingCard` хранит только состояние анимации: прогресс и координаты.
- `CardsGuiScreen` сохраняет раскладку, ввод, жизненный цикл экрана, инвентарь и отправку сетевых команд. Экран напрямую использует выделенные классы.
- Версия сборки, метаданные мода и путь JAR в README обновлены до 1.1.5. Скриншоты остаются подписанными v1.1.4; новые кадры этой версией не заявлялись.

Серверная и предметная логика, сеть, MongoDB, каталог, игровые тесты, ассеты, шейдер и шрифты не изменялись. Выделение `GuiLayout` и `GuiTheme` на этом этапе оставалось задачей v1.1.6.

## Проверки

- Тело каждого оставшегося метода `CardsGuiScreen` сравнено с базой v1.1.4 без различий.
- Все три класса кнопок, рисование поверхностей и состояние анимации сравнены с базой; изменены только видимость и содержащий класс.
- Локальная сборка `clean build test check runeInventoryRegression` прошла на окончательных исходниках 1.1.5.
- В переобфусцированном JAR проверены выделенные классы, отсутствие прежних вложенных классов экрана, версия 1.1.5 в `mcmod.info` и манифесте.
- Регрессии проверяют фиксированный каталог из 26 позиций, ранги, пробуждение и блокировку покупки.
- Сборки feature, develop, main и тега в GitHub CI прошли.

На момент первоначальной подготовки документа интерактивный проход Minecraft не выполнялся. После публикации пользователь подтвердил успешную проверку в игре. Рекомендуемый набор для дальнейших изменений: открытие/закрытие, полный/широкий/компактный размеры окна, поиск, вкладки статусов, количество покупки, анимация, пробуждение и очистка blur. Сравнение исходников и сборка не проверяют OpenGL в игре.
